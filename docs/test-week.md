# 시험 주간과 시험 날짜 (초옹장 2026-10-05 ~ 10-11)

오늘 날짜로는 할 일이 거의 오지 않습니다. 목업 리뷰는 11/13에서 끝나고, 메뉴판·포스터는 정해진 요일에만 옵니다. 그래서 **초옹장(s005) 한 주에 할 일이 고루 오도록 시험 데이터를 넣고**, 앱에서 **그 주의 알림 시각으로 서버 시계를 옮기는 "시험 날짜"** 를 만들었습니다.

## 1. 쓰는 법

1. 서버 `python run_dev.py`(시계 옮기기 켜짐, `DEV_TOOLS_ENABLED=true`), 앱 `npm run web` → http://localhost:8082
2. 시작 화면 **☰ › 데모 테스트 모드** 켜기
3. **☰ › 시험 날짜** (로그인 뒤에는 **설정 맨 아래 "시험 날짜"**): 10/5(월)~10/11(일)의 알림 시각과 그때 홈에 오는 할 일이 보입니다.
4. 시각을 누르면 서버 시계가 그 알림 5분 뒤로 옮겨지고, 홈이 그 시각의 할 일을 보여 줍니다.
5. 끝나면 **실제 시각으로**.

- `dona_demo`로 가입해 초옹장을 고르면 그 계정 가게가 초옹장이 됩니다. 로그인 전에는 초옹장으로 봅니다.
- 서버 시계는 서버에 하나라서, 옮기면 그 서버를 쓰는 모든 화면이 그 시각을 봅니다.

## 4. 어떻게 동작하나

- **팀 목업 파일(`db/data/s005.db`, `common.db`)은 고치지 않습니다.** 서버가 읽을 때 시험 행을 겹칩니다(`app/data_pipeline/test_scenario.py` → `read_store_db.py`). 분석·계획·매출·리뷰 화면이 모두 같은 데이터를 봅니다. 목업 생성기를 다시 돌려도 시험 데이터는 남습니다.
- 시험 데이터가 없는 가게는 아무것도 바뀌지 않습니다. 다른 가게에도 넣으려면 `db/test_scenarios/<가게>.json`을 만들면 됩니다(`week`, `weather`, `events`, `orders`, `reviews`).
- 이 데이터는 시험 주간뿐 아니라 언제 계산해도 초옹장 데이터에 들어 있습니다. 예를 들어 9/19 행사 효과는 그 뒤 달력에도 남습니다.
- API (개발자 대시보드와 같은 `DEV_TOOLS_ENABLED=true`일 때만)
  - `GET /api/dev_tools/test_week?store_id=s005`: 그 주 알림 시각마다 오는 할 일. 몇 초 걸려서 시험 데이터와 설정이 그대로면 기억해 둔 값을 씁니다.
  - `POST /api/dev_tools/test_go` `{"store_id", "at"}`: 서버 시계를 옮기고, 그 주 첫 알림 시각부터 고른 시각까지 차례로 계산해 결과를 보관합니다. 반복 불만은 처음 찾은 시각을 이어 써야 하기 때문입니다. 시계를 바로 옮겨 처음부터 계산하면 점검 승인 요청이 늘 다음 날로 밀립니다.
  - `POST /api/dev_tools/demo_clock_reset`: 실제 시각으로 돌립니다.
- 시계를 옮길 때 CLOVA 답글 초안은 기다리지 않습니다(써 둔 것만 바로 쓰고 나머지는 뒤에서 씀). 카드 문장 다듬기도 맡기지 않습니다.

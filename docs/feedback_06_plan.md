## A. 할 일 카드와 리뷰 보여 주기 (1, 2, 3)

### A1. 급한 카드 표시 (1)
- **지금**: 연한 빨강 바탕(`urgent-soft`)에 빨간 글씨 알약 "오늘 답글 필요" (`lib/cards.ts` quickReply).
- **검토**: 맞는 지적이다. "오늘"은 카드가 오늘 화면에 있으니 이미 알고, 사장님이 알아야 할 건 "다른 카드보다 먼저"다.
- **수정안**
  - 알약 문구 **"긴급"**, 진한 빨강 바탕(`urgent` #a3291c)에 흰 글씨 (대비 6.9:1, 기준 4.5 넘음).
  - 카드 테두리도 빨강 2px로 바꿔 다른 카드와 한눈에 구별.
  - 쓰는 곳: 불만 답글 승인 카드(05-4, 05-39)만. 반복 불만(05-10)은 지금처럼 "같은 불만 3번"(연한 빨강) 유지 → 급함은 하나만 진하게.
- **확인할 것**: "긴급" / "급해요" / "지금 답글" 중 하나. 추천은 사장님 제안대로 **"긴급"**.

### A2. 리뷰를 말풍선으로 (2)
- **지금**: 카드 안 "따옴표 글", 답글 화면은 테두리 네모(`ReviewBox`), 그 아래 도나 초안 말풍선.
- **검토**: 손님 말 → 도나 답이 **대화처럼** 보이면 "무슨 리뷰에 무슨 답을 다는지"가 바로 읽힌다. 05-4에서 이미 도나 초안이 말풍선이라 짝이 맞는다.
- **수정안**
  - 손님 리뷰 = **왼쪽 말풍선**(흰 바탕, 꼬리 왼쪽 위), 위에 작게 "배달의민족 손님, 별 1개".
  - 도나 초안 = **오른쪽 말풍선**(연한 갈색, 도나 얼굴 오른쪽), 지금보다 한 칸 들여서 대화 순서가 보이게.
  - 적용: 오늘 카드(05-4, 05-11, 05-35, 05-39), 답글 화면(05-5, 05-11r, 05-35r, 05-39r), 좋은 리뷰 묶음(05-25, 05-25b), 점검 목록의 리뷰 3개(05-24).
  - 컴포넌트 1개(`ReviewBubble`)로 묶는다.

### A3. 긴 리뷰와 리뷰 사진 (3)
- **지금**: 리뷰 전문을 그대로 보여 준다. 데모 리뷰는 짧아서 문제가 안 보이지만, 실제 배달앱 리뷰는 5~10줄도 흔하다. 사진은 데이터에도 없다.
- **검토**: 작은 칸 안에서 따로 스크롤되는 방식은 휴대폰에서 화면 스크롤과 겹쳐 손이 헛돈다(사용하기 어려운 사장님에게 특히). **3줄까지 보이고 "더 보기"로 펼치는 방식**을 추천한다.
- **수정안**
  - 말풍선 안 글은 3줄까지, 넘으면 끝에 "… 더 보기" (누르면 그 자리에서 펼침, "접기").
  - 오늘 카드에서는 3줄, 답글 화면에서는 6줄까지.
  - **사진(결정 필요)**: 추천은 "리뷰에 사진이 있으면 말풍선 아래 작은 사진 최대 3장(64px), 누르면 크게". 특히 "사진과 다름", "양이 적어요", "위생" 불만은 사진을 봐야 답을 정할 수 있다.
    - 보여 주지 않기로 하면: "사진 2장" 글자만 두고 배달앱으로 이동.
- **서버**: `reviews[]`에 `photos: [{ url, width, height }]` 추가. 목업 리뷰 2~3건에 사진 자리를 넣는다.

## B. 점검 목록 말투 (4)

- **지금**: 제목 "배달 지연 점검", 본문 "이렇게 점검해 봐요" + 할 일 3개(조리 순서 정하기 등) + "다 점검했어요".
- **검토**: 맞는 지적이다. 장사를 오래 한 사장님에게 앱이 **방법을 가르치는** 말투라 거부감이 생길 수 있다. 도나가 아는 건 "손님이 뭐라고 했는지"와 "언제 몰렸는지"이고, 방법은 사장님이 더 잘 안다.
- **수정 방향 (추천)**: **가르치기 → 사실 알려 드리기 + 사장님이 고르기**
  - 제목: "배달 지연 점검" → **"배달이 늦다는 말이 3번 나왔어요"**
  - 위: 손님 말풍선 3개(A2), 그 아래 **도나가 찾은 것** 사실만: "3번 모두 금요일, 토요일 저녁 7시쯤이에요", "주문이 몰린 시간과 겹쳐요" (주문 데이터로 계산 가능).
  - 할 일 목록은 지시가 아니라 **"다른 가게는 이렇게 하기도 해요"** 로 낮추고 접어 둔다(기본 닫힘).
  - 버튼: "다 점검했어요" → **"확인했어요"** (주) / "이미 알고 있어요" (보조). 무엇을 고르든 일주일 뒤 결과 알림(05-44)은 그대로.
  - 오늘 카드(05-10) 문구도 "같은 불만 3번" 알약 유지, 본문 "조리, 배달 순서를 점검해요" → "언제 늦었는지 정리해 뒀어요".
- **서버**: 점검 근거(불만 리뷰가 몰린 요일과 시간대). `REVIEW_FIX` 항목에 `pattern: { weekdays, hour_from, hour_to }` 제안.

### D2. 날씨 문구에 날씨 아이콘 (9)
- **지금**: "수요일부터 추워져요"는 국 그릇 아이콘(soup), 메뉴판 카드 "내일부터 추워져요"는 아이콘 없음, 이번 주 "오늘부터 추워져요"도 아이콘 없음(오른쪽 날씨 칸만 있음).
- **수정안**: 날씨 이유에는 날씨 아이콘을 먼저 둔다.
  - 추워져요 = **온도계 + 아래 화살표**(또는 눈송이), 더워져요 = 온도계 + 위 화살표, 비 = 비구름.
  - 적용: 월요일 미리 보기(05-16), 메뉴판 계절 카드(05-12, 05-12n, 05-14), 이번 주 이유 칸(05-7 계열), 바쁜 날 자세히(05-18), 매출 예상 이유("추워져요").

## E. 처음 쓰는 날: 네이버 플레이스로 불러오기 (10)

### 검토
- 맞는 지적이다. 지금 흐름(가게 찾기 → **장사 모양 고르기** → 장사 시간 직접 입력 → 알림 시간)은
  - 사장님이 이미 네이버 플레이스에 적어 둔 걸 **다시 입력**하게 하고,
  - "점심·저녁 장사 / 저녁·밤 장사 / 아침부터 저녁까지"처럼 **임의로 묶어** 실제 가게(요일마다 다른 시간, 일요일만 단축 등)와 안 맞는다. 장사 시간도 한 줄(여는·닫는 시간 하나)이라 요일별 차이를 못 담는다.
- 도나의 원칙("사장님은 보고 누르기만", 첫 행동은 최소)과도 맞다.

### 수정안: 새 흐름
1. **우리 가게 찾기 (05-2 그대로)** → "우리 가게 맞아요"
2. **네이버 플레이스 연결 (새, 06-2n)**
   - "네이버 플레이스를 연결하면 장사 시간, 메뉴, 사진을 불러올게요" + 불러올 것 그림 3개 + "가격과 사진은 건드리지 않아요"(기존 안심 문구 재사용).
   - 주 버튼 "네이버로 연결하기", 보조 "나중에 할게요(직접 적을게요)".
3. **불러왔어요 확인 (새, 06-2c)** — 한 화면에 요약, 줄마다 "고치기"
   - 장사 시간: **요일별**(예: 월 쉬어요 / 화~토 11:00~21:00 / 일 11:00~20:00), 브레이크 타임 15:00~17:00
   - 메뉴 12개 (위 3개 이름), 메뉴 사진 9장
   - 리뷰 207개 (기존 "함께 찾았어요" 줄을 여기로)
   - 주 버튼 "이대로 좋아요". 줄을 누르면 그 항목만 고치는 시트(장사 시간은 요일별 시간 시트).
4. **알림 시간 (05-3 그대로)**: 불러온 장사 시간으로 계산.
5. **알림 켜기 (05-3b 그대로)**

- 진행 막대는 그대로 4칸(가게, 연결, 확인, 알림).
- **연결을 건너뛰면**: 지금의 장사 시간 확인 화면(05-2i)을 직접 입력용으로 쓰되, **요일별 입력**으로 바꾼다.
- **장사 모양 고르기(05-2h) 처리 — 결정 필요**: 추천은 **없앤다**. 직접 입력 화면이 기본값을 채워 주면 충분하다.
- 따라오는 변경
  - 메뉴판 카드의 "도나에게 맡기기 → 네이버 연결"(05-50, 05-51)은 처음에 연결했으면 나오지 않는다. 건너뛴 사장님에게만 남긴다.
  - 설정 "네이버 플레이스"(05-58)에 "다시 불러오기"(장사 시간, 메뉴 바뀌었을 때) 추가.
  - 설정 "장사 시간"(05-19h)도 요일별 표시와 고치기.

### 데이터와 서버
- `settings`에 **요일별 장사 시간** 필요: `hours: { MON: { open, close, break? } | null, ... }`. 지금 `open_time`, `close_time`, `break_time`, `closed_weekdays`는 여기서 계산해 둘 수 있다.
- 알림 시각 계산(`lib/hours.ts`)도 요일별로: 요일마다 출근 후 시각이 달라질 수 있다 → **알림 시각을 요일마다 다르게 할지, 가장 이른 요일에 맞출지** 정해야 한다. 추천: 화면은 하나로 단순하게(가장 많은 요일 기준), 단축 영업 요일은 마감 전 알림만 그날 맞춤.
- `POST /api/naver/connect` → `GET /api/naver/place` (가게 정보, 요일별 영업시간, 메뉴, 사진, 리뷰 수).
- ⚠️ **확인 필요(팀)**: 네이버는 사장님 매장 정보를 가져오는 **공개 API가 없다**(검색 API는 이름, 주소, 업종 정도). 스마트플레이스 연동 방식(제휴, 사장님 로그인 후 가져오기 등)을 팀이 정해야 한다. 프론트는 목업으로 먼저 만든다. (`frontend_plan_v4.md` 10장 "네이버 메뉴 순서 바꾸기 공개 API"와 같은 문제)

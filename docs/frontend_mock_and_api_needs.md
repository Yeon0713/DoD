## 1. 지금 서버 API를 화면이 쓰는 방법

### 1-1. 불러오는 방식
- 앱은 화면마다 따로 부르지 않고 **`useHomeData()` 한 번에 5개를 같이** 부른다 (`src/lib/useHomeData.ts`, TanStack Query 키 `["home"]`). 오늘, 이번 주, 설정, 답글, 점검 화면이 모두 이 값을 같이 쓴다.
- 받은 값은 `localStorage`의 `dona.home.v3`에 저장해 두고, 다음에 열 때 먼저 그린 뒤 뒤에서 새로 받는다 (04-8b).
- 지금은 **`from`, `to`를 보내지 않는다**. 서버가 기간을 생략하면 전부 주는 규칙(가이드 4-1)에 기대고 있다. 데이터가 늘어나면 오늘 기준 앞뒤 기간을 정해 보내야 한다 (6장 할 일).
- `GET /api/sales`는 **쓰지 않는다**. 이번 주 화면의 평소/예상 매출은 `calendar`의 `baseline_sales`, `expected_sales`로 그린다.

### 1-2. API별로 읽는 필드

| API | 쓰는 화면 | 읽는 필드 | 프론트에서 하는 가공 |
|---|---|---|---|
| `GET /api/today` | 오늘 | `batches[].slot_at`, `entries[].plan_id / notice_id / notify_kind / priority` | 오늘 날짜이면서 이미 지난 알림 시각의 묶음만 보여 줌. `plan`과 id로 조인. 우선순위 1→4, 같으면 `deadline_at` 빠른 순. 같은 `execute_at`의 `BASIC` 답글은 카드 1장 (`src/lib/queue.ts`) |
| `GET /api/plan` | 오늘, 답글, 점검, 메뉴 순서, 포스터, 이번 주 자세히 | `plan_items[]` 전부 (`task_type`, `revisit_class`, `basis.kind/ref_id`, `target_date`, `approval_request_at`, `execute_at`, `deadline_at`), `notice_items[]` (`kind`, `text`, `refs`) | `execute_at`이 지금보다 뒤면 "그때 올려요/바꿔 둘게요"(예약), 지났으면 "지금 올리기"로 나눔 |
| `GET /api/calendar` | 이번 주, 이번 주 자세히, 월요일 미리 보기 카드, 메뉴판·포스터 카드 문구 | `cells[]`의 `date`, `daypart`, `signal`, `baseline_sales`, `expected_sales`, `reasons[].tag/ref_id`, `reason_text` | 날마다 "바쁨" 표시, 행사가 시작·끝나는 날 계산(`dayChange`), **행사·경기 이름을 `reason_text`에서 글자로 찾아냄** (3장 M) |
| `GET /api/reviews` | 답글, 점검 목록, 처음 쓰는 날 | `review_id`, `platform`, `written_at`, `rating`, `text`, `label.complaint_types / complaint_groups / sentiment` | 점검 목록은 `target_date` 전 7일의 같은 불만 리뷰를 모음 |
| `GET /api/settings` | 설정, 알림 시각, 가게 찾기, 포스터 | `name`, `category`, `store_id`, `slots`, `dayparts`, `busy_dayparts`, `open_time`, `close_time` | 가게 이름 끝 괄호 `(가상 매장)`은 지우고 보여 줌 |
| `PATCH /api/settings` | 알림 받는 시간, 바쁜 장사 시간 | 오류 `SLOT_IN_BUSY_DAYPART`, `SLOT_OUTSIDE_OPEN_HOURS`, `INVALID_INPUT` | 오류 메시지 앞의 `OPENING/AFTERNOON/CLOSING`으로 어느 칸 아래에 띄울지 정함. **이 형식을 서버가 바꾸면 안 된다** (또는 `error.field`를 따로 주면 그걸 쓰도록 바꿈) |

### 1-3. 고정 샘플 모드에서만 하는 일 (서버 연결 후에는 서버가 할 일)
- **알림 묶음 만들기**: 예시 `today`는 화요일 하루뿐이라, 서버와 같은 규칙(`server/app/planner/priority_and_grouping.py` → `src/lib/grouping.ts`)으로 `plan`에서 데모 주간 모든 날의 묶음을 만든다.
- **알림 시각 옮기기** (`src/lib/slotRemap.ts`): 예시 계획은 10:00, 14:00, 21:30 기준으로 계산돼 있다. 사장님이 장사 시간이나 알림 시각을 바꾸면 같은 이름의 알림 시각으로 옮긴다. 새벽 알림(예: 01:30)은 다음 날로, 쉬는 날의 알림은 다음 장사하는 날로 옮기고, 승인이 실행보다 늦어지면 실행 알림을 하루씩 미룬다. **서버는 새 시각으로 계획을 직접 다시 계산해야 한다** (지금은 설정을 바꿔도 다시 계산하지 않음, 가이드 4-9).
  - 고친 문제: 전에는 시각이 정확히 맞는 계획만 묶어서, 알림 시각을 바꾸면 그 시각의 카드가 모두 사라졌다.
- **답글 시각 규칙 "시안 규칙"**: `/dev`에서 고르는 값. 좋은 리뷰 묶음을 금요일 오후 승인, 토요일 출근 후 올림으로 바꾸고, 주간·월간 단골 답글 2건(`rv_102`, `rv_087`)을 프론트에서 끼워 넣는다 (`applyDesignRule`). **서버 규칙과 시안 중 하나로 팀이 정해야 한다** (plan v4 10장).

## 3. 서버에 새로 필요한 것

이름과 모양은 **제안**이다. 여헌과 정한 뒤 이 표를 고친다. 응답은 모두 지금 서버 규칙(`is_example`, 오류 `{"error": {"code", "message"}}`, 시각 `+09:00`)을 따른다고 가정한다.

### A. 답글 초안 (`plan` 항목에 필드 추가)
- **화면**: 04-5, 04-11r, 04-25, 04-35r, 04-39r, 재주문 권유 인사
- **지금**: `mockDraft(review)`, `mockNudge(review)` (`src/mocks/extras.ts`), 리뷰 id별 고정 문장
- **제안**: `plan_items[]`에 `draft_text: string | null` 추가. `REORDER_NUDGE`는 답글이 아니라 **다시 찾아 달라는 인사말**이어야 한다 (테스트에서 월간 단골 답글이 그대로 들어가던 문제를 고침).

### B. 답글 다시 쓰기
- `POST /api/replies/{plan_id}/rewrite`
- 요청 `{ "text": "지금 글", "style": "SHORT" | "POLITE" }` → 응답 `{ "text": "새 글" }`
- 프론트는 받은 글을 바로 보여 주고, "다 고쳤어요"를 누를 때까지 저장하지 않는다.

### C. 답글 올리기
- `POST /api/replies/{plan_id}/publish`
- 요청 `{ "text": "올릴 글" }` (생략하면 서버 초안) → 응답 `{ "published_at": "...+09:00", "platform": "BAEMIN" }`
- 오류: 플랫폼 로그인 만료, 리뷰 삭제됨 등은 `code`를 나눠 주면 화면 문구를 나눈다. 지금은 모든 실패를 "인터넷이 끊겼어요"로 보여 준다.

### D. 카드 처리 상태 (다 했어요, 나중에)
- **지금**: `localStorage` `dona.cardState.v1`에 `카드id → {kind: "done"} | {kind: "snoozed", until}`. 다른 기기에서는 처리한 카드가 다시 나온다.
- **제안**: `PATCH /api/plan/{plan_id}` `{ "notify_kind": "APPROVAL_REQUEST" | "EXECUTE_REMINDER", "status": "DONE" | "SNOOZED", "snooze_until": "...+09:00" }`
- 알림(`notice_items`)도 같은 처리가 필요하다: `PATCH /api/notices/{notice_id}` `{ "status": "DONE" | "SNOOZED", "snooze_until" }`
- `today` 응답에서는 처리한 항목을 빼고, 미룬 항목은 `snooze_until` 시각의 묶음에 다시 넣어 준다.
- **카드 id 규칙** (프론트가 지금 쓰는 것): `{notify_kind}:{plan_id 또는 notice_id}`. 좋은 리뷰 묶음은 `BASIC:{notify_kind}:{execute_at}`.

### E. 승인만 하고 나중에 실행 (예약)
- **화면**: 단골 답글 "이대로 좋아요", 좋은 리뷰 묶음 "4개 모두 올려 주세요", 재주문 권유, 알아서 바꾸기를 켠 메뉴판 "좋아요"
- **제안**: `POST /api/plan/{plan_id}/approve` `{ "text"?: "고친 글" }` → `{ "scheduled_at": "...+09:00" }`. 묶음은 `POST /api/plan/approve` `{ "plan_ids": [...] }`.
- 서버가 실행 시각에 자동으로 올리는지(서버 규칙: 토요일 11시 자동), 사장님이 실행 알림에서 다시 누르는지(시안: 토요일 10시 "4개 모두 올리기")를 **팀이 정해야** 한다. 지금 프론트는 시안대로 실행 알림에서 한 번 더 누른다.

### F. 가게 찾기 (처음 쓰는 날 04-2)
- **지금**: 설정의 가게 이름과 글자가 겹치면 찾은 것으로 침. 주소는 `STORE_ADDRESS` 고정 값, 리뷰 수는 `reviews` 응답 개수.
- **제안**: `GET /api/stores/search?q=국수` → `{ "stores": [{ "store_id", "name", "address", "review_counts": { "BAEMIN": 120, "NAVER": 40 } }] }`, 고른 뒤 `POST /api/stores/select` `{ "store_id" }`
- `settings`에 `address` 필드 추가 (설정 화면 맨 위에 씀).

### G. 처음 쓰는 날의 지난 리뷰 (04-4f)
- **지금**: `plan`의 좋은 리뷰 묶음(`BASIC`)을 "답글 없는 지난 리뷰"로 보여 준다.
- **제안**: `GET /api/reviews?unanswered=true` 또는 처음 연결한 날 서버가 `BASIC` 묶음을 바로 만들어 줌.

### H. 네이버 플레이스와 메뉴 순서
- 연결: `POST /api/naver/connect` (실제로는 네이버 로그인 화면으로 보내고 돌아오는 주소가 필요), 끊기 `DELETE /api/naver/connect`
- 연결 상태와 알아서 바꾸기: `settings`에 `naver_connected: boolean`, `auto_menu_order: boolean` 추가, `PATCH /api/settings`로 `auto_menu_order` 고침. **지금은 기기에만 저장**(`dona.prefs.v1`)이라 다른 기기에서 다르게 보인다.

### Z2. 07 홈: 오늘 끝낸 일 (07-1, 07-2, 07-4)
- 홈의 "오늘 끝낸 일"은 지금 이 기기의 카드 상태(`dona.cardState.v1`)에서 만든다. 끝낼 때 **끝낸 시각(`at`)**, **한 일(`note`, 예: "답글을 올렸어요")**, **올린 답글(`reply`)**을 같이 저장한다. 다른 기기에서 열거나 앱을 지우면 사라진다.

## 1. 화면으로 다시 보기 (브라우저)

**왜:** 이번 작업은 서버 시험과 앱 타입 검사(`tsc`)만 통과했습니다. 앱을 실제로 띄워 보지는 않았습니다. 특히 교정 카드가 **긴급(맨 위 붉은 카드, 퇴근 막힘)에서 "확인 필요"(퇴근 막지 않음)**로 바뀌어, [test-scenarios-closed-loop.md](test-scenarios-closed-loop.md)의 W5·W6 결과는 바뀌기 전 것입니다.

### 준비

```bash
cd server && .venv/bin/python -m voice.run_voice          # 백엔드 (8100)
cd donna-voice/app && npm run web                          # 앱 (http://localhost:8090)
```

- 처음부터: `curl -X POST localhost:8100/v1/dev/fixtures -H 'Content-Type: application/json' -d '{"fixture":"s005_choongjang"}'`
- 사장님 화면: http://localhost:8090 · 알바생 화면: http://localhost:8090/staff · 시연: `/demo` · 개발자 모드: `/dev`
- 시각 옮기기: `curl -X POST localhost:8100/v1/dev/clock -H 'Content-Type: application/json' -d '{"now":"2026-11-17T15:40:00+09:00"}'`
- 시연 리뷰 넣기: `curl -X POST localhost:8100/v1/dev/demo_review -H 'Content-Type: application/json' -d '{"store_id":"s005","name":"leak"}'` (`leak`, `missing`, `cold`, `hall`)
- 바로 답하기 켜고 끄기: 설정 탭 "아쉬운 리뷰 바로 답하기", 또는 `curl -X PATCH localhost:8100/v1/settings -H 'Content-Type: application/json' -d '{"store_id":"s005","negative_review_auto_reply":true}'`

## 2. 시연 저장본에 현장 변수 할 일이 없음

**지금 상태:** `server/voice/fixtures/s005_choongjang.prepared.json`(시연 아침 11/17 09:02)을 다시 만들었습니다. 아침 할 일 질문에는 **리뷰 교정 하나만** 나옵니다.
> "어젯밤 면이 불어서 왔다는 리뷰 때문이에요." → "알바생 할 일에 면 불지 않게 배달하기를 넣을까요?"

**왜 현장 변수가 없나:** 저장본을 다섯 번 만드는 동안 현장 변수 사원이 낸 결과는 이랬습니다.

| 번 | 결과 |
|---|---|
| 1 | "우산 준비(손님께 빌려줄 우산)", "땅콩 알레르기 손님 테이블 분리". 품질 팀장이 실패해 모두 남음 |
| 2 | "땅콩 알레르기 손님용 좌석 배치". 팀장이 남김 (알레르기를 막는 일이 아님) |
| 3 | CLOVA 오류로 제안 없음 |
| 4 | "땅콩 알레르기 손님 우산 준비" (날씨와 예약을 섞음). 이 뒤에 근거별 손님 정보 검사를 더함 |
| 5 | CLOVA 오류로 제안 없음 ← **지금 저장본** |

**할 것**
1. 시연에서 현장 변수(비 → 할 일, 알레르기 예약 → 할 일)를 보여 줄지 정합니다.
2. 보여 준다면 저장본을 다시 만들고 결과를 눈으로 확인합니다. 마음에 들지 않으면 다시 만듭니다.

   ```bash
   cd server
   .venv/bin/python -c "from Harness import cache; cache.clear_disk()"   # 사원 결과를 새로 받으려면 (안 지우면 같은 결과가 재사용됨)
   .venv/bin/python -m voice.prepared_snapshot s005_choongjang            # CLOVA, 1분 30초 ~ 3분 40초
   ```

3. 확인하는 법 (제안과 아침 질문 출력):

   ```bash
   python3 -c "
   import json; d=json.load(open('voice/fixtures/s005_choongjang.prepared.json'))
   for x in d['docs']:
       if x['kind']=='proposal': v=x['data']; print(v['by'], v['state'], v['payload'].get('title'), '|', v['payload'].get('detail'), '| 팀장', (v.get('lead') or {}).get('verdict'))
       if x['kind']=='briefing': s=x['data']['steps'].get('staff_tasks'); print([t['text'] for t in s['say']] if s else None)
   "
   ```

4. 저장본을 바꾸면 커밋합니다(`server/voice/fixtures/s005_choongjang.prepared.json`).

**주의:** 저장본을 만들 때마다 CLOVA 비용이 듭니다. 사원 결과가 매번 달라서, 만든 뒤 반드시 위 출력을 보고 문장이 이상하지 않은지 확인해야 합니다.

## 3. 현장 변수 사원 CLOVA 오류 (40009) 원인

**지금 보이는 것:** 저장본을 만들 때 이런 기록이 자주 나옵니다.

```
CLOVA(도구) 강제 호출 400, 조건을 바꿔 다시 묻는다: {"status":{"code":"40009","message":"Unsupported function"},"result":null}
CLOVA(도구) 응답 400: {"status":{"code":"40009","message":"Unsupported function"},"result":null}
```

- 같은 사원이 성공한 적도 있어서 늘 실패하지는 않습니다.
- 실패하면 제안 없이 끝납니다(안전한 쪽). 그날 다음 준비 때 다시 해 봅니다.

**의심 가는 곳:** 제출 도구 `submit_field_tasks`([field_tasks.py](../../server/voice/agents/field_tasks.py))는 **객체 목록 안에 enum과 boolean이 섞인 모양**이라, 다른 사원보다 복잡합니다. 팀장 `submit_lead`([team_lead.py](../../server/voice/agents/team_lead.py))도 비슷한 모양이고, 실패한 적이 있습니다.

**할 것**
1. 실패한 요청의 도구 모양을 실행 기록에서 찾습니다. 기록은 `server/db/app_data/harness_trace.db`, CLOVA 사용 기록은 `server/db/app_data/clova_usage.db`, 개발자 대시보드 '에이전트' 탭에서도 볼 수 있습니다.
2. 같은 요청을 몇 번 보내 늘 실패하는지 확인합니다.
3. 늘 실패하는 모양이면 제출 도구를 단순하게 바꿉니다. 예: 할 일을 하나씩 내게 하기, enum을 string으로 두고 코드에서 검사하기.

## 4. 평가 세트 정답 검토

**왜:** 정답은 제가 붙인 초안입니다(`verified_by: 초안 … 팀 검토 전`). 프롬프트에 예시를 늘리지 않고 평가 세트로 판정을 재기로 했으니(결정 6), 이 세트가 기준이 됩니다.

| 세트 | 파일 | 무엇을 보나 | 지금 결과 (2026-11-20, 실제 CLOVA 한 번) |
|---|---|---|---|
| 교정 카드 | [fix_cases.json](../../server/Harness/evals/data/fix_cases.json) (12건) | 리뷰마다 "알바생이 다음 근무에서 막을 수 있었나"(`actionable`)와 카드에 들어가면 안 되는 말(`must_not`) | 판정 11건 모두 맞음, 1건 물러남(CLOVA 실패), 할 수 없는 일 0건 |
| 같은 할 일 | [dedupe_cases.json](../../server/Harness/evals/data/dedupe_cases.json) (8쌍) | 두 할 일이 알바생에게 같은 행동을 시키나(`same`) | 바이그램만 5/8, LLM까지 7/8, 잘못 묶음 0 |

**할 것**
1. 정답이 맞는지 봅니다. 특히 판단이 갈릴 만한 것:
   - `f04` "물 달라고 했는데 한참 뒤에 줬어요" → 조치 가능(true)으로 둠
   - `f07` "가격에 비해 양이 너무 적어요" → 조치 불가(false). 양은 사장님 결정으로 봄
   - `d03` "주문서 대조"와 "수저 챙기기" → 다른 일(false)
   - `d08` "땅콩 알레르기 확인" 두 문장 → 같은 일(true)
2. 사례를 늘립니다. 특히 실제 리뷰에서 가져온 것, 현장 변수(날씨·예약 메모) 사례가 아직 없습니다.
3. 검토가 끝나면 `verified_by`를 고칩니다.
4. 다시 재기:

   ```bash
   cd server
   .venv/bin/python -m Harness.evals fixcard
   .venv/bin/python -m Harness.evals dedupe --systems dice,dice+judge
   ```

   결과는 `server/db/app_data/harness_eval/<스위트>-<시각>/result.json`에 남습니다(git에 올라가지 않음).

## 5. 교정 카드·현장 변수 문장의 질

**왜:** 평가는 "조치할 수 있나"만 재고, 카드 문장이 상황에 맞는지는 재지 않습니다. 실제로 나온 문장 중 아쉬운 것:

| 리뷰 / 근거 | 나온 카드 | 아쉬운 점 |
|---|---|---|
| (배달) "젓가락이 안 왔어요." | 손님에게 젓가락 가져다주기 | 배달이라 "봉투 닫기 전 수저 넣었는지 보기"가 맞음 |
| "만두가 눌려서 다 터져서 왔어요." | 만두를 조심스럽게 다루기 | 무엇을 어떻게 할지가 막연함 |
| 예약 메모 "땅콩 알레르기 손님 1명 있어요" | 땅콩 알레르기 손님용 좌석 배치 | 알레르기를 막는 일(음식 확인)이 아님 |

**지금 막고 있는 것:** 리뷰·메모 인용이 글자 그대로 있어야 함, 가격·보상 금지, 알바생이 할 수 없는 일(사기·바꾸기·정책) 질문, 손님 정보는 그 할 일의 근거에만, 프롬프트 원칙 "근거가 된 문제를 직접 막는 일".

**할 것**
1. 문장 적합을 재는 평가(심판)를 더할지 정합니다. 기존 답글 평가(`reply` 스위트)의 심판 방식을 쓸 수 있습니다.
2. 더 막을 규칙이 필요하면, 예시 목록이 아니라 **원칙 한 줄**로 프롬프트에 넣습니다(결정 6).
3. 프롬프트를 고치면 캐시 열쇠가 바뀌어 저장본을 다시 만들 때 새로 받습니다(2번 참고).

## 6. 팀장 판단이 거의 늘 keep

**지금 보이는 것:** 실제로 돌린 다섯 번 모두 고객 응대·품질 관리 팀장은 사원 제안을 거의 다 남겼습니다. 이유도 "고객 불만족 해결책"처럼 뭉뚱그린 말이었습니다. 위 5번의 아쉬운 문장도 팀장이 걸러 내지 못했습니다.

**지금 되는 것:** 팀장 제출 검사(모든 결과에 판정이 있어야 함, drop에는 이유 필수)는 시험으로 확인했습니다. 실패하면 모두 남깁니다.

**할 것**
1. 팀장이 drop 해야 할 사례(근거를 막지 못하는 일, 이미 화면에 있는 일, 같은 날 같은 일)로 평가 세트를 만듭니다.
2. 결과를 보고 팀장이 쓸모가 있는지 판단합니다. 쓸모가 적으면 끌 수 있습니다(`VOICE_AGENT_LEAD=false`). 끄면 사원 결과가 모두 남고, 영업 중 알림이 최대 15초 빨라집니다.

## 8. 운영 조건

| 무엇 | 조건 | 확인할 것 |
|---|---|---|
| 기상청 날씨 | 메인 서버(8000, `python run_dev.py`)가 켜져 있어야 자정에 받음. 음성 백엔드만 켜면 새로 받지 않음 | 시연·운영 때 메인 서버를 같이 켜는지 |
| 날씨 받는 가게 | 등록한 가게만(`registered_stores`). 초옹장(s005)은 시연 가게라 일부러 시나리오 날씨를 씀 | 실제 가게(s101~)를 등록해 다음 날 `voice/weather.py`가 날씨를 읽는지 |
| 네이버 휴무 | 가게를 **등록할 때 저장한** 휴무 안내·소식 글만 읽음. 그 뒤 새 소식은 다시 읽지 않음. 초옹장은 등록 기록이 없어 읽을 글이 없음 | 소식을 다시 읽을지 (open-features 9장) |

| 영업 중 알림 시간 | 교정 카드 LLM(30초 예산) + 팀장(15초)으로 알림이 최대 약 45초 늦어질 수 있음 | 실제 시연에서 알림까지 걸리는 시간 |
| 마케팅 사원 | 인스타를 연결한 가게만 돎 | 연결한 가게에서 소재·글이 나오는지, 글 끝 영업시간·휴무 줄 |

# 도나 개발자 대시보드 (로컬 시험용)

서버 속(가게 데이터, 분석 결과, 알림 계획, CLOVA 비용과 품질)을 한눈에 보고, 시계 앞당기기·다시 계산·초기화를 하는 웹 페이지입니다.
앱 화면의 글을 화면별로 보고 고쳐서 앱 코드에 바로 넣는 **화면 글** 탭도 여기에 있습니다.
설치나 빌드가 없는 HTML/CSS/JS 이고, 우리 서버가 같은 주소에서 보여 줍니다.

## 켜는 법

1. `server/.env`에 두 줄을 넣습니다.
   ```
   DEV_TOOLS_ENABLED=true
   DEV_CLOCK_ENABLED=true
   ```
   - `DEV_TOOLS_ENABLED`: 대시보드 화면과 대시보드용 API(`/api/dev_tools/...`)를 엽니다.
   - `DEV_CLOCK_ENABLED`: 조작 탭의 시계 앞당기기와 데모 초기화를 씁니다 (팀원이 만든 `/dev/clock`, `/dev/reset`).
2. 서버를 켭니다 (README 2장). `.env`를 고쳤으면 서버를 껐다 다시 켜야 합니다.
3. 브라우저에서 **http://localhost:8000/dev-dashboard/** 를 엽니다.
   - 탭 이름을 붙이면 그 탭부터 열립니다. 예) `http://localhost:8000/dev-dashboard/#ai`. 연 뒤에 주소의 `#탭이름`만 바꿔도 그 탭으로 갑니다.
   - 예전 탭 이름(`#overview`, `#system`, `#usage`, `#quality`)도 합친 탭으로 열립니다.
   - 주소에 `?cursor=1` 을 붙이면 누르는 곳이 보이는 시연용 마우스 표시가 켜집니다 (`?cursor=0` 끄기, 이 브라우저에 기억). 휴대폰 틀 속 앱에도 같이 켜집니다. 예) `http://localhost:8000/dev-dashboard/?cursor=1#demo`
4. 서버가 켜지면 모든 가게의 시연 기간을 뒤에서 미리 훑어 둡니다 (가게 하나에 2~14초). 결과는 `server/db/app_data/demo_scans/` 에 남아서 서버를 다시 켜도 바로 씁니다.

배포 서버에서는 두 값을 켜지 않습니다. 모든 가게 데이터와 AI 기록이 보이고 초기화도 할 수 있기 때문입니다.

## 시연 탭 (Figma UC01~UC16)

시연에서 늘 같은 화면이 뜨도록, 실제 오늘이 아니라 **정해 둔 시연 기간 2026-11-09(월) ~ 11-22(일)** 의 서버 시각으로 앱을 엽니다.
(목업 리뷰가 11/10까지 있어서 이 주를 골랐어요. 첫 주에 불만 답글·좋은 리뷰 묶음·포스터가, 둘째 주에 메뉴판 바꾸기가 나와요.)

1. 서버 `.env`에 `DEV_TOOLS_ENABLED=true`, `DEV_CLOCK_ENABLED=true` (시계를 옮겨야 해서 둘 다 필요)
2. 앱을 웹으로 켭니다: `cd mobile && npm run web` (http://localhost:8082). 주소가 다르면 시연 탭 왼쪽 "앱 주소"를 고칩니다.
3. 대시보드 **시연** 탭 → 위 **가게**에서 가게를 고릅니다. 서버가 켜질 때 미리 훑어 두므로 바로 열려요. 아직 훑는 중이면 "훑는 중 n / 42"가 보이고 가게 하나에 2~14초 걸려요 (CLOVA는 부르지 않음). 왼쪽 "시연 준비"에서 가게마다 준비됐는지 보입니다.
4. 휴대폰 틀은 앱을 `127.0.0.1:8082` 로 띄웁니다. 평소 쓰는 앱(`localhost:8082`)과 브라우저 저장 공간이 따로라서, 시연 단계가 휴대폰 틀에 넣는 로그인·가게·카드 상태가 평소 앱에 남지 않습니다 (예전에 `localhost` 로 적어 둔 앱 주소도 `127.0.0.1` 로 바꿔 씁니다). 다만 **서버 시계는 하나**라서 평소 앱도 같은 시각을 봅니다.
   휴대폰 틀에는 처음부터 지금 서버 시각의 앱 홈이 떠 있습니다. 가운데 단계를 누르거나 **다음 ▶** 을 누르면: 서버 시계를 그 단계 시각으로 옮기고 → 그 가게를 다시 계산하고(약 1초) → 휴대폰 틀에 그 화면을 엽니다. 언제든 **[앱 홈]** 으로 돌아갑니다.
   - 단계를 열 때 CLOVA 답글 초안은 기다리지 않습니다. 이미 써 둔 초안은 바로 쓰이고, 처음 보는 리뷰의 초안은 뒤에서 써서 앱을 다시 불러오면 보입니다.
   - 카드 문장 다듬기(CLOVA)는 기본으로 끕니다. 다듬은 문장으로 시연하려면 왼쪽 **단계마다 문장 다듬기**를 켭니다 (CLOVA 비용이 나갑니다).
5. 끝나면 왼쪽 **시연 끝내기 (시계를 실제 시각으로)** 를 누릅니다. 휴대폰 틀도 실제 시각의 앱 홈으로 돌아갑니다.
6. 화면 폭이 좁으면(1200px 아래) 휴대폰 틀과 [이전]/[앱 홈]/[다음]이 맨 위에 옵니다.

- 회색 단계는 그 가게 데이터에 그 장면이 없는 것이고, 까닭이 적혀 있어요. 예) 두리맥주는 새벽까지 장사해서 계획이 없음, 같은 불만 3번·단골 재주문 인사·매출 이상은 지금 시연 기간에 어느 가게에도 없음, 불러오기 늦음·끊김은 목업 모드 전용.
- 답글 초안 글은 서버를 켤 때마다 CLOVA가 새로 써서 문장이 조금 달라질 수 있어요. 카드와 화면 순서는 늘 같아요.
- 만든 곳: (서버) `dev_tools/demo_week_scan.py` 시연 기간 훑기(미리 훑기, 파일 저장, 진행), `dev_tools/demo_scenario.py` UC별 단계, (앱) `mobile/src/app/demo-jump.tsx` 입구 화면.
- 훑은 결과는 `server/db/app_data/demo_scans/<가게>.json` 에 남습니다 (git 제외). 가게 DB, 공통 DB, 그 가게의 등록 정보, 사장님이 고친 설정, 계산 코드 중 하나라도 바뀌면 다시 훑습니다 (다른 가게를 등록하거나 지워도 이 가게 결과는 그대로 씁니다). 직접 다시 훑으려면 **이 가게 다시 훑기**.

## 화면 글 탭 (앱 화면 글 고치기)

앱 화면의 글을 **화면별로 모아 보고, [수정] 칸에 적어 앱 코드에 바로 넣는** 탭입니다. 코드를 열어 글을 하나씩 찾지 않아도 됩니다.
주소: **http://localhost:8000/dev-dashboard/#uitext**

서버 컴퓨터에 Node.js 와 `mobile/node_modules`(mobile 폴더에서 `npm install`)가 있어야 합니다. 서버가 앱 쪽 스크립트를 불러 글을 읽고 고칩니다.

### 쓰는 법

1. 왼쪽에서 화면을 고릅니다. 화면 이름, 경로, **그 화면에서 할 수 있는 것**이 위에 나옵니다.
2. 줄마다 `종류(제목, 버튼, 설명, 띠, 시트 안 버튼 …) | 원본 | [수정]` 입니다. 제목이 맨 위, 그 다음 화면 본문 글, 그 다음 화면이 쓰는 부품의 글 순서입니다.
3. [수정] 칸에 바꿀 글을 적으면 바로 `mobile/scripts/ui-text/edits.json` 에 저장됩니다. 비워 두면 그대로 둡니다. 줄 바꿈은 화면의 줄 바꿈이 됩니다.
4. 다 적었으면 **코드에 넣기** → 바꿀 목록을 확인하고 **바꾸기**. 앱 코드(`mobile/src`)의 글이 바뀌고 타입 검사(tsc)를 돌려 결과를 보여 줍니다.
5. 넣은 수정은 edits.json 에서 빠지고, 탭을 다시 열면 **원본 칸이 수정본으로** 바뀌어 있습니다. 앱(8082)은 저절로 새로 고쳐집니다.

- 위 검색 칸: 모든 화면에서 글을 찾습니다.
- "이 화면이 같이 쓰는 글": 여러 화면이 함께 쓰는 글(카드 문구, 요일 이름, 오류 문구 등)은 따로 묶여 있습니다. 여기서 고치면 쓰는 화면 모두 바뀝니다.
- 보라색 `${…}` 는 코드가 채우는 자리(가게 이름, 시각 등)입니다. **순서 그대로 남겨야** 넣어집니다.
- "읽어 주기 이름"은 화면에 보이지 않고, 화면 읽기 기능이 읽는 글입니다.
- "원본을 못 찾은 수정": 저장한 뒤 코드가 바뀌어 원래 글이 없어진 수정입니다. 새 원본을 찾아 다시 적고 지웁니다.

### 밖에서 JSON 으로 고치기

대시보드 없이 파일 하나만 들고 고칠 때 씁니다. 파일 안에 글마다 원본이 그대로 적혀 있고, 따로 붙인 ID 같은 연결 데이터는 없습니다.

1. **JSON 내려받기** (또는 `cd mobile && npm run ui-text:export -- <저장할 파일>`). 화면마다 `이름`, `경로`, `하는 일`(그 화면의 기능)이 있고, 글마다 아래 칸이 있습니다.

   ```json
   { "종류": "제목", "위치": "components/start/StartScreens.tsx:56 · IntroScreen", "원본": "매장 운영,", "수정": "" }
   ```

   `${…}` 자리가 있는 글에는 `"그대로 둘 자리": ["${name}"]` 가 붙습니다. 여러 화면이 같이 쓰는 묶음에는 `"쓰는 화면"` 목록이 붙습니다.
2. 밖에서 `"수정"` 칸만 채웁니다. 비워 두면 그대로 둡니다. `"원본"`, `"위치"` 는 고치지 않습니다.
3. **JSON 등록**으로 고친 파일을 올립니다 (또는 `npm run ui-text:import -- <파일>`). `"원본"` 글로 코드의 자리를 찾아 edits.json 에 더하고, 같은 글이 여러 곳에 있으면 `"위치"`(파일, 함수, 가까운 줄)로 고릅니다.
   - 대시보드에서는 담은 글이 노란색으로 보이고, 바로 **바꿀 목록 확인 창**이 뜹니다. **바꾸기**를 누르면 코드에 들어갑니다.
   - 못 담은 글(원본을 못 찾음, `${…}` 자리가 빠짐 등)은 까닭과 함께 위에 보입니다.

### 대시보드 없이 넣기

edits.json 을 직접 고친 뒤:

```bash
cd mobile && npm run ui-text:apply
```

### 어떻게 동작하나

- `mobile/scripts/ui-text/core.mjs` 가 `src/app`, `src/components`, `src/lib` 을 TypeScript 파서로 읽어 한글이 든 글을 모읍니다. 주석, import, 타입, 비교에 쓰는 문자열(`=== "점심"`, `startsWith("인사")`)은 뺍니다. `src/mocks`(목업 데이터)와 서버가 보내는 글은 대상이 아닙니다.
- 화면 경로 파일(`src/app/**`)에서 시작해 그 화면이 부르는 함수를 따라가 글을 화면별로 묶습니다. 개발 화면(`/dev`)은 개발 화면 파일 안에서만 따라갑니다.
- 화면 이름과 설명은 `mobile/scripts/ui-text/screens.json` 에 있습니다. 화면이 새로 생기면 여기에 한 줄 더하세요.
- 수정은 `파일 + 함수 + 원본 글` 로 찾아 넣습니다. 코드가 바뀌어 원본을 못 찾으면 넣지 않고 "원본을 못 찾은 수정"으로 남깁니다.
- 서버(`server/app/modules/dev_tools/ui_text.py`)는 `node mobile/scripts/ui-text/cli.mjs data|save|apply|export|import` 를 부르고 그 JSON 을 그대로 화면에 넘깁니다.
- 잘못 넣었으면 git 으로 되돌리면 됩니다 (`git diff`, `git checkout -- <파일>`).

## CLOVA 비용 계산

- CLOVA를 부를 때마다 `server/app/core/clova_usage_log.py`가 기능, 가게, 입력·출력 토큰, 걸린 시간, 통과/버림을 `server/db/app_data/clova_usage.db`에 남깁니다 (git에 올라가지 않음).
- 비용(원) = 토큰 수 × 단가 ÷ 1,000. 단가는 `server/.env`의 `CLOVA_PRICE_INPUT_PER_1K`, `CLOVA_PRICE_OUTPUT_PER_1K`에 네이버 클라우드 CLOVA Studio 요금표를 보고 넣습니다. 비어 있으면 대시보드에 "단가 미설정"으로 보입니다.
- 리뷰 분류의 HyperCLOVA X 호출(태성 `hcx_classifier.py`)은 지금 꺼져 있어서 기록하지 않습니다.

## 앱의 개발용 시뮬레이터와 나눈 것

앱(설정 › 개발 화면)의 개발용 시뮬레이터 중 **서버에서 돌아가는 것**은 이 대시보드로 옮겼습니다: 가상 시각, 지금 시각의 카드(알림 타임라인), 답글 시각 규칙, 초기화.
**앱 기기 안의 것**(이 기기 상태, 화면 바로 열기, Figma 화면 바로 가기, 문제 상황 흉내)은 앱 저장소와 화면을 직접 바꾸므로 앱의 개발 화면에 그대로 둡니다.

## 4. 2026-11-22 수정 뒤 남은 할 일 (버그 아님)

고친 22건 때문에 따로 챙겨야 하는 것입니다.
1. **batch 평가 다시 돌리기**: H3·H6 수정으로 평가 숫자(`conflicts_left`, 재작업, 근거 없는 숫자)가 바뀝니다. 실제 CLOVA를 부르므로 아직 돌리지 않았습니다. H10을 고친 뒤 `python -m Harness.evals batch --systems R,A,B`로 돌리고, 예전 결과 폴더와 섞어 비교하지 않습니다.
2. **판정 물러나기 비율 보기**: H4 수정으로 음성 서버의 엄격 판정(intent_judge, same_task)은 동시 호출 자리를 3~5초까지만 기다립니다. 못 잡으면 어림짐작 판정으로 넘어가므로 `judge_fallback_rate`를 봅니다(`Harness.evals voice`, `intent`).
3. **다시 쓰기를 앱 화면에 붙일 때**: `REWRITE_SPEC.fallback_after_deadline`을 False로 바꿀지 정합니다(H7). False면 시간이 넘었을 때 None이 돌아오므로 화면이 빈 결과를 처리해야 합니다. 실측 p95를 보고 15초 예산도 다시 정합니다.
4. **trace DB 옮기기**: H5 수정으로 trace DB가 WAL 모드가 되어 옆에 `-wal`, `-shm` 파일이 생깁니다. DB를 옮길 때 함께 옮깁니다.
5. **가게 파일을 다루는 새 코드**: A1 수정으로 가게마다 엔진을 따로 둡니다. 가게 파일을 만들거나 지우는 코드는 꼭 `db.session.dispose_all()`을 부릅니다. 공통 `engine`으로 가게 테이블을 직접 읽으면 실패합니다.
6. **개발 문서 고치기**: A2 수정으로 늦게 여는 가게는 답글 올리는 시각이 `max(11:00, 여는 시각+30분)`입니다. "토요일 11시 고정"으로 적힌 `docs/development.md` 등을 고칩니다.

## 5. 시험 돌리는 법

시스템 python에는 pytest가 없습니다. 꼭 `server/.venv/bin/python`을 씁니다. 지금은 아래 시험이 모두 통과합니다. 위 버그들은 기존 시험이 다루지 않는 경로에 있습니다.

```
cd server
.venv/bin/python -m pytest tests -q --ignore=tests/voice   # 기존 서버: 702 통과
.venv/bin/python -m pytest voice/tests -q                  # 음성: 455 통과, 2 건너뜀
.venv/bin/python -m pytest Harness/tests -q                # 하네스: 327 통과
```

예전 재현 시험(`repro/`)은 그 버그를 모두 고쳐서 지웠습니다. 남은 버그는 각 문서 "고친 뒤 확인"의 시험을 먼저 써서 실패하는 것을 본 뒤 고칩니다.

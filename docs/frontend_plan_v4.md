## 2. 기술 스택과 원칙

1차 계획서 1장을 그대로 따른다. 요점만 다시 적는다.

- **Next.js (App Router) + TypeScript + Tailwind CSS**, 모바일 웹 375px 기준, PWA
- **API 호출은 `frontend/src/lib/api.ts` 한 곳에서만** 한다. `NEXT_PUBLIC_USE_MOCK=true|false`로 고정 샘플과 실제 API를 바꾼다.
- 서버와는 영문 코드값으로만 주고받고, 화면 문구는 `lib/labels.ts`에서 만든다.
- 매장 이름 등 매장 정보는 화면에 직접 쓰지 않고 `GET /api/settings`에서 받는다. (시안의 "도나네 곱창 역삼점"과 샘플의 "춘천 대학가 국수집"이 달라도 코드는 그대로 동작한다.)

**추가 원칙 (04 시안에서 온 것)**
1. **한 화면에 한 가지**: 화면마다 주 버튼은 1개다. 보조 버튼("나중에 할게요", "고쳐 쓰기")은 테두리만 있는 버튼으로 1개까지 둔다.
2. **사장님이 누르기 전에는 아무것도 밖으로 나가지 않는다**: 답글 올리기, 메뉴 순서 바꾸기, 인스타 보내기는 모두 버튼을 누른 뒤에만 API를 부른다. 단, 사장님이 "다음부터 알아서"를 켠 메뉴 순서 바꾸기만 예외다.
3. **글자는 14px 이상**, 본문 18px. 누르는 곳은 높이 48px 이상.

## 5. 홈 불러오기 규칙 (04-8 규칙 보드)

사장님이 가장 자주 보는 화면이라 따로 정해 둔다. `components/today/TodayLoader.tsx` 한 곳에서 처리한다.

| 걸린 시간 | 화면 | Figma |
|---|---|---|
| 0 ~ 0.3초 | 아무것도 바꾸지 않는다 (깜빡임 방지) | |
| 0.3초부터 | 카드 모양 뼈대 + 왼쪽에서 오른쪽으로 지나가는 빛 (계속 반복) | 04-8, 컴포넌트 `03/뼈대 빛` |
| 3초 넘으면 | 도나 한마디 "조금만 기다려 주세요" | 04-8c |
| 10초 넘으면 | "생각보다 오래 걸려요" + 다시 불러오기 버튼 | 04-8d |
| 다시 열 때 | 지난번 카드를 바로 보여 주고, 위 진행 막대만 "새 할 일 확인 중" | 04-8b |
| 인터넷이 끊겼을 때 | "할 일은 그대로 있어요" + 다시 불러오기 | 04-9 |

- 지난번 카드는 `localStorage`에 마지막 `today` + `plan` 응답으로 저장해 두고 다시 열 때 먼저 그린다.
- 빛 움직임은 CSS `@keyframes`로 만들고, `prefers-reduced-motion`이면 움직이지 않는 뼈대만 보여 준다.
- 이번 주 화면도 같은 규칙을 쓴다 (04-7L 불러오는 중, 04-7E 끊겼을 때).

## 6. 상태 관리

- **서버 데이터**: TanStack Query. 키는 `['today']`, `['plan', from, to]`, `['calendar', from, to]`, `['settings']`
- **오늘 화면 줄 세우기**: `lib/queue.ts`. `today.batches[].entries`를 `plan` 응답과 id로 붙이고, 우선순위 1 → 4, 같으면 `deadline_at` 빠른 순으로 정렬한다. 같은 실행 시각의 `BASIC` 답글은 1장으로 묶는다 (1차 계획서 `groupers.ts`와 같다).
- **카드 처리 상태** (다 했어요, 나중에, 올렸어요): 서버 API가 생기기 전까지 `localStorage`에 `planId → 상태`로 둔다. 처리한 카드는 줄에서 빼고, 다 빠지면 04-6을 보여 준다.
- **첫 사용 여부**: `localStorage`의 `onboarded` 값이 없으면 `/`에 들어왔을 때 `/start`로 보낸다.

## 7. API: 지금 있는 것과 더 필요한 것

### 7-1. 지금 API로 그릴 수 있는 화면

| API | 화면 |

## 9. 화면 검증 방법

1. **Figma 대조**: 화면마다 Figma 스크린샷(375 × 812)과 같은 크기로 찍은 브라우저 스크린샷을 나란히 놓고 본다. 글자 줄바꿈 위치, 버튼 높이, 색을 확인한다.
2. **프로토타입 흐름 대조**: Figma의 흐름 시작점 25개(`v4 1` ~ `v4 24`, `v4 Flow 3`)를 하나씩 눌러 보며 같은 순서로 화면이 바뀌는지 본다.
3. **줄바꿈**: 한국어 문장은 Figma처럼 줄을 직접 나눈 곳이 많다. 문구 안의 줄바꿈은 `labels.ts`에 `\n`으로 두고 `white-space: pre-line`으로 그린다. 단어 중간에서 줄이 바뀌지 않게 `word-break: keep-all`을 전체에 건다.

## 11. 구현 현황 (2026-11-10, 브랜치 `jheroorehj/feat-frontend`)

Figma 04 섹션의 화면 04-1 ~ 04-66을 모두 만들었고, 브라우저(375 × 812)에서 하나씩 열어 Figma와 대조했다. 코드는 `frontend/`, 실행 방법은 [`frontend/README.md`](../frontend/README.md).

**화면이 아닌 프레임**은 만들지 않았다: 04-0 원칙 보드, 04-8 홈 불러오기 규칙 보드, 04-7A/04-7B/04-7C(이번 주 시안 고르기, C를 04-7로 구현), 04-60 자리(포스터는 카드에서 시작한다는 안내).

**검토 방법**: 개발용 시뮬레이터 `/dev`의 "Figma 04 화면 바로 가기"에서 화면 번호를 누르면, 그 화면에 맞는 가상 시각과 상태로 열린다.

**만들면서 정한 것**
- **앱을 열면 오늘 화면**이 바로 나온다. 처음 쓰는 날 흐름(04-1 ~ 04-3b)은 `/start`에 있고, 설정의 "우리 가게 다시 찾기"와 `/dev`에서 들어간다. 서버가 "가게 없음"을 알려 주게 되면 그때 처음 쓰는 날로 보낸다.
- **알림이 꺼져 있어요 띠(04-4n)**는 "켜기"를 누르면 바로 닫힌다. 브라우저가 알림을 막으면 "휴대폰 설정에서 알림을 허용해 주세요" 띠로 알려 준다. 위에 뜨는 띠(04-5s)는 2초 뒤 사라지고, 누르면 바로 닫힌다.
- **데모 주간 모든 날의 카드**: 고정 샘플의 `today` 응답은 화요일 하루뿐이라, 고정 샘플 모드에서는 서버와 같은 규칙(`server/app/planner/priority_and_grouping.py` → `frontend/src/lib/grouping.ts`)으로 `plan` 응답에서 날마다 알림 묶음을 만든다. `/dev` 타임라인이 `docs/frontend_plan.md` 4장 정답표와 같다.
- **답글 시각 규칙**(고정 샘플 모드, `/dev`에서 바꿈): 기본은 "시안 규칙"이다. 좋은 리뷰 묶음은 금요일 오후 승인, 토요일 출근 후 올림(04-17, 04-40)이고, 주간 단골(04-11, 04-32)과 월간 단골(04-35, 04-38) 답글을 프론트 목업으로 넣는다. "지금 서버 규칙"을 고르면 서버 예시 그대로(토요일 10시 승인, 11시 자동 올림) 보여 준다.
- **메뉴판 카드의 네이버 상태**: 연결 전 처음에는 04-50(도나에게 맡기기), "제가 직접 할게요"를 고른 뒤에는 04-12형(좋아요), 연결하면 바꿀 순서 미리 보기, 알아서 바꾸기를 켜면 실행 때 04-56.
- 카드 처리 기록, 고쳐 쓴 답글, 네이버 연결, 처음 쓰는 날 여부는 서버 API가 생기기 전까지 이 기기(`localStorage`)에 둔다.
- 고정 샘플 모드에서 `PATCH /mock-api/settings`는 서버와 같은 검사를 하고 메모리에만 저장한다.

**전체 흐름 검증 (2026-11-11)**: 데모 주간의 모든 알림 시각에서 카드를 끝까지 눌러 보고, 실패·끊김·느림 상황까지 확인했다. `next build` 성공. 고친 것과 서버에 필요한 API·데이터는 [`frontend_mock_and_api_needs.md`](./frontend_mock_and_api_needs.md)에 모았다.

**아직 못 한 것**
- 실제 API 모드(`NEXT_PUBLIC_USE_MOCK=false`) 대조.
- 실제 휴대폰 푸시 알림(웹 푸시, 알림톡)은 2차. 지금은 04-23을 `/lock` 화면으로 보여 주고, `/dev`의 "휴대폰 알림 보내 보기"로 브라우저 알림만 띄워 본다.

# 테스트 네이버 계정 (dona_test1~3)

임시 네이버 로그인 화면(진짜 네이버 키가 없을 때)에서 쓰는 테스트 계정입니다. 2026-11-13에 계정마다 시험할 일을 정하고, 조건을 DB 표 하나로 관리하게 바꿨습니다.

## 1. 왜 바꿨나

- 예전에는 세 계정 모두 "사장님 1 (김한림)"처럼 이름만 달랐습니다. 하는 일은 똑같았습니다(가게 없이 가입 → 지도에서 가게 찾기). 화면만 보는 개발자는 어느 계정이 어느 가게로, 무엇을 시험하는지 알 수 없었습니다.
- 그래서 계정마다 **시험할 장면 하나**를 정했습니다.
  - 등록 흐름을 매번 처음부터 시험하는 계정
  - 할 일이 많이 쌓인 하루를 시험하는 계정 두 개
- 조건은 코드가 아니라 **DB 값**으로 고치게 했습니다. 시험할 가게나 날짜를 바꾸고 싶으면 DB 한 칸만 고치면 됩니다.

## 2. 세 계정

| 계정 (비밀번호 `dona1234`) | 가게 | 로그인하면 | 로그아웃하면 |
|---|---|---|---|
| **dona_test1** | 없음 (매번 찾음) | 등록 기록을 보지 않고 **늘 네이버 지도에서 가게 찾기 · 등록 → 처음 설정**. 앱 기록도 지우고 시작 | 서버 시계와 앱 기록을 처음으로 |
| **dona_test2** | 한림국수 (s001) | 서버 시계를 **2026-09-10(목) 21:35**로 옮김 → 처음 설정부터 시작 → 홈에 할 일 4개 | **전부 초기화**: 그 가게의 고친 설정·계산, 서버 시계, 앱 기록(처음 설정, 끝낸 카드, 고쳐 쓴 답글) → 다음 로그인도 처음부터 |
| **dona_test3** | 석사돈가스 (s003) | 서버 시계를 **2026-09-23(수) 20:35**로 옮김 → 첫 로그인은 처음 설정부터, 다음부터는 보관해 둔 상태 그대로 홈 | **남김**: 처음 설정, 끝낸 카드, 고쳐 쓴 답글을 계정별로 보관했다가 다시 로그인하면 되살림 |

임시 네이버 로그인 화면의 "테스트 계정 보기"와 개발자 대시보드 **상태** 탭의 "테스트 네이버 계정" 표에 가게와 설명(`scenario`)이 그대로 보입니다.

## 3. 할 일이 많은 장면을 고른 방법

1. 목업 DB(지호 님 `server/db/data`, 2026년 1년치)에서 가게마다 날짜별로 계산했습니다.
   - s002 두리맥주는 자정을 넘겨 영업해서 계획을 만들지 못하므로 뺐습니다.
   - 계산 시각은 날마다 마감 전 알림 5분 뒤(1/15~12/10)였습니다.
   - 센 값은 그날 홈에 온 할 일 수입니다.
2. 시연 기간(11/9~11/22)에는 하루 최대 2개뿐이었습니다. 1년 전체에서는 하루 **최대 4개**였습니다. 4개인 날 가운데 할 일 종류가 가장 다양한 날을 골랐습니다.

| 계정 | 장면 | 그날 온 할 일 (알림 시각) |
|---|---|---|
| dona_test2 | s001 한림국수 · 9/10(목) 21:35 | 10:00 불만 리뷰 답글 승인 · 10:00 메뉴판 순서 되돌리기 실행 알림 · 10:00 포스터 올리기 실행 알림 · 21:30 불만 리뷰 답글 승인 |
| dona_test3 | s003 석사돈가스 · 9/23(수) 20:35 (강원대 대동제 날) | 10:30 불만 리뷰 답글 승인 · 10:30 행사 메뉴판 실행 알림 · 15:30 날씨 메뉴판 승인 · 15:30 포스터 승인 |

리뷰는 11/10까지만 있어서, 불만 답글까지 섞인 날은 그 전 날짜에서 골랐습니다.

## 4. DB

- 파일: **`server/db/test_accounts.db`** (SQLite, git에 같이 올라갑니다. 팀 모두 같은 조건으로 시험합니다)
- 파일이 없으면 서버가 `server/app/modules/auth/test_accounts.py`의 `DEFAULT_ACCOUNTS` 값으로 만듭니다.
- 이 파일은 지워지지 않습니다.
  - 목업 생성기(`python -m db.mock.generate`)는 `db/data`만 다시 만듭니다.
  - 데모 초기화(`/dev/reset`)는 `db/app_data`만 지웁니다.
- 고친 값은 **서버를 다시 켜지 않아도 다음 로그인부터** 씁니다 (로그인할 때마다 DB를 읽습니다).

표 `test_accounts` (한 줄이 계정 하나)

| 칸 | 뜻 |
|---|---|
| `login_id`, `password` | 임시 네이버 로그인 아이디·비밀번호 (시험용 값) |
| `naver_id`, `profile_json` | 네이버 회원 번호 자리와 프로필 (`/v1/nid/me`와 같은 모양). 등록 기록 `owners`의 `naver:<naver_id>`와 이어짐 |
| `find_store` | `1`이면 로그인할 때마다 등록 기록을 보지 않고 가게 찾기부터 |
| `store_id` | 로그인하면 들어갈 가게 (예: `s001`). 비우면 이 계정으로 등록해 둔 가게 |
| `scene_at` | 로그인하면 서버 시계를 이 시각으로 옮김 (예: `2026-09-10T21:35:00+09:00`). **서버를 `DEV_CLOCK_ENABLED=true`로 켰을 때만** (`run_dev.py`는 켜 둠) |
| `on_logout` | `reset` 로그아웃하면 전부 처음으로 / `keep` 남김 |
| `scenario` | 화면에 보일 설명 |

고치는 예 (`server` 폴더에서)

```bash
sqlite3 db/test_accounts.db "SELECT login_id, find_store, store_id, scene_at, on_logout FROM test_accounts"
```

```bash
sqlite3 db/test_accounts.db "UPDATE test_accounts SET scene_at = '2026-09-16T21:35:00+09:00' WHERE login_id = 'dona_test2'"
```

DB Browser for SQLite 같은 프로그램으로 열어 고쳐도 됩니다. 계정을 더 만들려면 줄을 하나 더 넣습니다 (`naver_id`는 겹치지 않게).

## 5. 어떻게 동작하나

**서버** (`server/app/modules/auth/`)
- `test_accounts.py`: DB를 읽고(없으면 만들고) 계정마다 들어갈 가게(`login_store`)와 화면 설명(`where_it_goes`)을 정합니다.
- `router.py`
  - **로그인 결과**: 임시 로그인이 끝나면 DB 조건대로 가게를 정합니다(`find_store`면 없음, `store_id`, 아니면 등록 기록). `scene_at`이 있으면 서버 시계를 옮기고 그 가게 계산을 지웁니다. 앱에 주는 결과(`GET /api/auth/naver/result/{ticket}`)에 `test_account: {login_id, on_logout, scene_at}`를 붙입니다.
  - **`POST /api/auth/test/logout`** `{"login_id"}`: `reset`이면 그 가게의 고친 설정과 계산(`store_snapshot_cache.reset_store`)을 지우고 서버 시계를 실제 시각으로 돌립니다. `keep`이면 아무것도 지우지 않습니다.

**앱** (`mobile/src/lib/testAccount.ts`)
- 이 기기 기록 = 처음 설정(`dona.prefs.v1`), 끝낸 카드(`dona.cardState.v1`), 고쳐 쓴 답글(`dona.drafts.v1`), 홈 저장본
- **로그인** (`onTestLogin`, 네이버 로그인 화면에서 결과를 받은 직후):
  - `reset` 계정: 이 기기 기록을 지웁니다 → 처음 설정부터
  - `keep` 계정: 그 계정 몫으로 보관해 둔 기록(`dona.keep.testAccount.<아이디>`)을 되살립니다 → 처음 설정을 마쳤으면 바로 홈
  - 서버가 옮긴 시계를 앱도 다시 읽습니다(`refreshServerClock`).
- **로그아웃** (`onTestLogout`, 설정 › 계정 › 로그아웃):
  - `keep` 계정: 기록을 계정 몫으로 보관하고 그대로 둡니다 → "다시 오셨네요" 로그인 화면
  - 서버에 로그아웃을 알립니다.
  - `reset` 계정: 기록을 지웁니다 → 시작 화면
- 보관본은 `dona.keep.`으로 시작해서, 서버를 다시 켜거나 앱 ☰ 초기화를 해도 남습니다. test2로 처음부터 시험해도 test3의 기록은 남습니다.

## 6. 알아 둘 것

- **서버 시계는 서버에 하나**입니다. test2·test3으로 로그인하면 그 서버를 쓰는 모든 화면(대시보드, 다른 탭의 앱)이 그 날짜를 봅니다. 실제 시각으로 돌리려면 test2 로그아웃, 개발자 대시보드 시연 탭 [시연 끝내기], 또는 조작 탭 [실제 시각으로]를 씁니다.
- test1은 가게를 등록할 때마다 등록 기록에 그 계정 연결이 남지만, 로그인할 때 보지 않으므로 매번 가게 찾기부터 합니다. 같은 네이버 플레이스를 다시 고르면 같은 등록 가게(s101 …)를 다시 씁니다.
- test3의 보관본은 **그 브라우저(기기)에만** 있습니다. 다른 브라우저에서 로그인하면 처음 설정부터 합니다.
- 장면 시각의 홈을 처음 열 때 서버가 그 가게를 계산하면서 답글 초안을 CLOVA로 씁니다 (키가 있으면 비용이 나갑니다).
- 시험: `server/tests/modules/test_naver_login.py`
  - 계정별 조건
  - 장면 시각으로 시계 옮기기
  - 로그아웃 reset·keep
  - DB 기본값과 고친 값 바로 적용
  - 화면 설명

테스트는 실제 DB 대신 임시 DB를 씁니다(`tests/conftest.py`).

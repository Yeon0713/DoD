## 1. 화면 시나리오

**11/21 한 것:** 실제 백엔드에 1장 순서를 API로 보내고, 응답과 알바생 화면 데이터(`/v1/staff/today`, `/v1/staff/tasks/{id}`)를 확인했습니다. 앱은 서버가 준 `urgent`, `tag`, `until`, `sub`(작은 글씨)를 그대로 그립니다. 인스타 게시가 필요한 1-6·1-14는 실제 계정에 올라가므로 시험(가짜 Graph)으로 확인했습니다. **남은 것은 화면 모양(글자 넘침, 칸 위치)을 브라우저로 보는 것뿐입니다.**

### 준비

```bash
cd server && .venv/bin/python -m voice.run_voice          # 백엔드 (8100)
cd donna-voice/app && npm run web                          # 앱 (http://localhost:8090)
```

- 처음부터: `curl -X POST localhost:8100/v1/dev/fixtures -H 'Content-Type: application/json' -d '{"fixture":"s005_choongjang"}'`
- 사장님 화면: http://localhost:8090 · 알바생 화면: http://localhost:8090/staff · 시연: `/demo` · 개발자 모드: `/dev`
- 시각 옮기기: `curl -X POST localhost:8100/v1/dev/clock -H 'Content-Type: application/json' -d '{"now":"2026-11-17T15:40:00+09:00"}'` (09:30을 넘기면 브리핑을 다시 준비하느라 10초쯤 걸림, 2장)
- 시연 리뷰 넣기: `curl -X POST localhost:8100/v1/dev/demo_review -H 'Content-Type: application/json' -d '{"store_id":"s005","name":"leak"}'` (`leak`, `missing`, `cold`, `hall`)
- 직급 바꾸기 (2026-11-21 인사과, 예전 "바로 답하기 켜고 끄기" 자리): `curl -X POST localhost:8100/v1/dev/hr -H 'Content-Type: application/json' -d '{"store_id":"s005","ranks":{"negative_reply":"assistant"}}'` (대리 = 묻지 않고 올림, 인턴 = 알림 뒤 묻기, 사원 = 30분 묶음 창). 설정 토글과 `negative_review_auto_reply`는 없앴습니다 (인수인계 24장)
- 교정 카드를 템플릿으로 보려면: 셸이나 `server/.env`에 `VOICE_AGENT_FIXCARD=false`

## 2. 시연 저장본에 현장 변수 할 일이 없음

**지금 상태:** `server/voice/fixtures/s005_choongjang.prepared.json`(시연 아침 11/17 09:02)의 아침 할 일 질문에는 **리뷰 교정 하나만** 나옵니다.
> "어젯밤 면이 불어서 왔다는 리뷰 때문이에요." → "알바생 할 일에 면 불지 않게 배달하기를 넣을까요?"

이 제안의 고객 응대 팀장 판단은 `source: FALLBACK`입니다(팀장이 summary 길이 거절로 실패해 판단 없이 남김, 6장).

**왜 현장 변수가 없나 (11/21 실행 기록으로 다시 봄):** 저장본을 다섯 번 만드는 동안의 결과입니다. 문서에 "CLOVA 오류"로 적었던 것 중 **진짜 CLOVA 오류는 3번 하나뿐**이었습니다.

| 번 | 결과 | 실제 원인 |
|---|---|---|
| 1 | "우산 준비", "땅콩 알레르기 손님 테이블 분리". 품질 팀장이 실패해 모두 남음 | 팀장 summary 길이 거절 두 번 |
| 2 | "땅콩 알레르기 손님용 좌석 배치". 팀장이 남김 | — |
| 3 | 제안 없음 | CLOVA 40009 (3장) |
| 4 | "땅콩 알레르기 손님 우산 준비" (날씨와 예약을 섞음) | 이 뒤에 근거별 손님 정보 검사를 더함 |
| 5 ← **지금 저장본** | 제안 없음 | **우리 길이 검사.** 제목 "땅콩 알레르기 손님 대체 메뉴 준비"(16.5자 > 16)를 두 번 거절 |

**저장본 밖에서도 현장 변수 사원이 돕니다:** 사원이 성공해야 남는 표시(`field_run`)가 저장본에 없습니다. 그래서 **브리핑을 다시 준비할 때마다**(시계를 09:30 넘게 옮김, 리뷰를 넣음) 사원이 CLOVA로 다시 돌고(10~30초), 성공하면 그때 제안이 생깁니다. 오후 시연 중에 제안이 생기면 다음 "도나야" 때 "그 전에 하나만요."가 끼어들 수 있습니다. 0장 수정으로 40009가 사라졌지만, 11/21 실제로 3번 돌린 결과는 모두 실패였습니다(긴 제목을 줄이지 못함 2번, 할 수 없는 일 심판 1번, 3장).

**할 것**
1. 시연에서 현장 변수(비 → 할 일, 알레르기 예약 → 할 일)를 보여 줄지 정합니다.
2. 보여 주지 않는다면: 시연 서버를 `VOICE_AGENT_FIELD=false`로 켭니다(`server/.env`에 적어도 됨, 0장).
3. 보여 준다면 저장본을 다시 만들고 결과를 눈으로 확인합니다. 마음에 들지 않으면 다시 만듭니다.
   - **주의:** 0장의 교정 카드 수정 뒤로 "면이 불어서 왔어요"는 늘 조치 불가로 나옵니다(4장). 저장본을 다시 만들면 지금 아침 질문(면 불지 않게 배달하기)이 **사라질 수 있습니다.**
   - 0장 캐시 키 변경으로 처음 한 번은 모든 사원 결과를 새로 받습니다.

   ```bash
   cd server
   .venv/bin/python -m voice.prepared_snapshot s005_choongjang            # CLOVA, 1분 30초 ~ 3분 40초
   ```

4. 확인하는 법 (제안과 아침 질문 출력):

   ```bash

   import json; d=json.load(open('voice/fixtures/s005_choongjang.prepared.json'))

   ```

5. 저장본을 바꾸면 커밋합니다(`server/voice/fixtures/s005_choongjang.prepared.json`).

## 3. CLOVA 오류(40009) 원인 — 찾아서 고침

**무엇이었나:** 도구 제출을 강제한 요청에서 `{"status":{"code":"40009","message":"Unsupported function"}}`이 납니다. 요청 모양이 틀려서가 아닙니다. **모델이 답을 끝까지 만든 뒤** CLOVA가 그 생성을 도구 호출로 인정하지 않고 버린 것입니다. 그래서 400인데도 9~10초가 걸렸습니다.

**언제 났나:** 모델이 먼저 `submit_field_tasks`를 부르지 않고 글로 답함 → 하네스가 "반드시 … 도구로 제출해 줘"를 붙이고 제출을 강제 → 400. 앞서 쓴 글이 "오후 2시부터 비", "12:00 예약"처럼 시각 중심이라, 모델이 `phase` 칸에 그 시각을 넣으려 했습니다.

**어떻게 찾았나:** 실행 기록(`server/db/app_data/harness_trace.db`)으로 실패한 대화를 그대로 다시 만들어 조건을 하나씩 바꿔 보냈습니다.

| 조건 | 결과 |
|---|---|
| 그대로 | 400 ×3 |
| 앞의 글 답을 뺌 | 통과 |
| `today_impact` boolean → 문자열 / `source_type` enum 뺌 | 400 |
| `phase` enum 뺌 (설명은 "언제 할 일인가") | 통과하지만 phase에 "오후 2시부터", "12:00"을 씀 |
| `phase` enum 없이 설명에 영어 값 나열 ("before_open 문 열기 전, …") | 400 |
| `phase`를 **우리말 enum** (문 열기 전/영업 중/마감) | **통과 ×3, 값도 맞음** ← 이것으로 고침 |

영어 값(before_open 등)을 enum이나 설명에 보이면, 앞서 쓴 글에 끌린 모델이 다른 값을 쓰려다 생성이 깨지는 것으로 보입니다.

**아직 남은 현장 변수 실패 (40009 아님)**
- **긴 제목:** 거절 문구가 "지금 20자, 16자까지"라고 알려 줘도 모델이 **같은 제목을 그대로** 다시 냅니다. 다시 내라는 말을 바꿔 봐도(6번) 같았습니다. 제목 한도 16이 알바생 화면에 꼭 맞는 값인지 다시 보거나(넓히면 해결), 다른 방법이 필요합니다.
- **할 수 없는 일 심판(`staff_scope`)이 너무 엄격함:** "우산꽂이와 물받이 배치하기", "아이 의자 2개 준비", "땅콩 관련 식재료와 조리도구 분리"를 "알바생이 할 수 없는 일"로 거릅니다.
- 교정 카드에서도 같은 강제 제출 뒤 40009가 가끔 납니다(11/21 평가 16건 중 1건). 실패하면 템플릿으로 물러납니다(안전한 쪽).

## 4. 평가 세트 정답 검토

**왜:** 정답은 초안입니다(`verified_by: 초안 … 팀 검토 전`). 프롬프트에 예시를 늘리지 않고 평가 세트로 판정을 재기로 했으니(결정 6), 이 세트가 기준이 됩니다.

**11/21 바뀐 것**
- 실제 시연 리뷰 4건을 넣었습니다(`d_leak`, `d_missing`, `d_cold`, `d_hall`). 11/20의 "11건 모두 맞음"은 짧은 문장(`f01` "국물이 다 새서 봉투가 흥건했어요.")으로 한 번 잰 결과였고, 실제 시연 리뷰(앞에 메뉴 이름, 뒤에 "맛은 괜찮은데 포장 좀 신경 써 주세요")는 3/3 조치 불가였습니다.
- 한 번 재는 것으로는 부족합니다. 같은 문장도 매번 판정이 바뀝니다. 11/21 같은 리뷰를 5번씩 돌린 결과:

| 칸 설명 | leak (시연, 정답 T) | f01 (T) | f05 면 불음 (T) | f07 양 (F) | f08 입맛 (F) |
|---|---|---|---|---|---|
| 11/20 원래 | FFFFF | TTTTT | TFTFT | FFFFF | FFFFF |
| **11/21 지금** | xTxTT | TFTTT | **FFFFF** | FFFFF | FFFFF |
| (시험) 판정 칸을 맨 뒤로 | TTxTx | TTTTT | FFFFF | xFFTT | xFFFF |

  `x`는 실패해서 템플릿으로 물러난 것입니다(leak은 템플릿 카드가 나옴). 판정 칸을 맨 뒤로 옮기면 "양이 적어요"에도 카드를 내서 채택하지 않았습니다. **지금 설명의 대가는 f05(면이 불어서 왔어요)를 늘 조치 불가로 내는 것입니다.**

| 세트 | 파일 | 무엇을 보나 | 지금 결과 (2026-11-21, 실제 CLOVA 한 번) |
|---|---|---|---|
| 교정 카드 | [fix_cases.json](../../server/Harness/evals/data/fix_cases.json) (16건) | 리뷰마다 "알바생이 다음 근무에서 막을 수 있었나"(`actionable`)와 카드에 들어가면 안 되는 말(`must_not`) | 판정한 13건 중 12건 맞음(f05 틀림), 3건 물러남, 잘못 넣은 것 0건, 할 수 없는 일 0건 |
| 같은 할 일 | [dedupe_cases.json](../../server/Harness/evals/data/dedupe_cases.json) (8쌍) | 두 할 일이 알바생에게 같은 행동을 시키나(`same`) | 바이그램만 5/8, LLM까지 7/8, 잘못 묶음 0 (11/20) |

**할 것**
1. 정답이 맞는지 봅니다. 특히 판단이 갈릴 만한 것:
   - `f04` "물 달라고 했는데 한참 뒤에 줬어요" → 조치 가능(true)으로 둠
   - `f05` "면이 불어서 왔어요" → 조치 가능(true). 배달 시간 탓일 수도 있어 갈릴 만함. 지금 사원은 늘 false
   - `f07` "가격에 비해 양이 너무 적어요" → 조치 불가(false). 양은 사장님 결정으로 봄
   - `d_cold` "국물이 식어서 미지근하게 왔어요" → 조치 가능(true). 배달 시간 탓일 수도 있음
   - `d03` "주문서 대조"와 "수저 챙기기" → 다른 일(false)
   - `d08` "땅콩 알레르기 확인" 두 문장 → 같은 일(true)
2. 사례를 늘립니다. 현장 변수(날씨·예약 메모) 사례가 아직 없습니다.
3. 검토가 끝나면 `verified_by`를 고칩니다.
4. 다시 재기 (한 번이 아니라 여러 번 재서 흔들림을 보는 것을 권합니다):

   ```bash
   cd server
   .venv/bin/python -m Harness.evals fixcard
   .venv/bin/python -m Harness.evals dedupe --systems dice,dice+judge
   ```

   결과는 `server/db/app_data/harness_eval/<스위트>-<시각>/result.json`에 남습니다(git에 올라가지 않음). 같은 입력은 캐시를 쓰므로, 여러 번 재려면 `.venv/bin/python -c "from Harness import cache; cache.clear_disk()"`로 비웁니다.

## 5. 교정 카드·현장 변수 문장의 질

**왜:** 평가는 "조치할 수 있나"만 재고, 카드 문장이 상황에 맞는지는 재지 않습니다. 실제로 나온 문장 중 아쉬운 것:

| 리뷰 / 근거 | 나온 카드 | 아쉬운 점 |
|---|---|---|
| (배달) "젓가락이 안 왔어요." | 손님에게 젓가락 가져다주기 | 배달이라 "봉투 닫기 전 수저 넣었는지 보기"가 맞음 |
| "만두가 눌려서 다 터져서 왔어요." | 만두를 조심스럽게 다루기 | 무엇을 어떻게 할지가 막연함 |
| 예약 메모 "땅콩 알레르기 손님 1명 있어요" | 땅콩 알레르기 손님용 좌석 배치 | 알레르기를 막는 일(음식 확인)이 아님 |
| 날씨 "오후 2시부터 비" (11/21) | 12시 예약 손님 최대한 많이 받기 | 알바생 할 일이 아님 |
| 예약 메모 "땅콩 알레르기 손님 1명 있어요" (11/21) | 땅콩 알레르기 손님 우산 빌려드리기 | 날씨와 예약을 섞음 |

**11/21 더 본 것**
- 교정 카드 사원이 `actionable: false`를 내면서 제목은 채우는 일이 있습니다("포장 시 국물이 새지 않도록 주의"). 검사는 false면 바로 끝내므로 화면에는 나오지 않습니다.
- 모델이 긴 제목을 거절받아도 줄이지 못합니다(3장).

**지금 막고 있는 것:** 리뷰·메모 인용이 글자 그대로 있어야 함, 가격·보상 금지, 알바생이 할 수 없는 일(사기·바꾸기·정책) 질문, 손님 정보는 그 할 일의 근거에만, 프롬프트 원칙 "근거가 된 문제를 직접 막는 일".

**할 것**
1. 문장 적합을 재는 평가(심판)를 더할지 정합니다. 기존 답글 평가(`reply` 스위트)의 심판 방식을 쓸 수 있습니다.
2. 더 막을 규칙이 필요하면, 예시 목록이 아니라 **원칙 한 줄**로 프롬프트에 넣습니다(결정 6).
3. 프롬프트나 도구 모양을 고치면 캐시 키가 바뀌어 다음에 새로 받습니다(0장).

## 6. 팀장 판단

**11/21 전에 보인 것:** 실제로 돌린 7번 중 2번은 팀장이 summary를 폭 34 넘게 써서 두 번 거절받고 판단 없이 모두 남겼습니다(지금 저장본의 고객 응대 팀장 포함). 성공한 때도 거의 다 keep이었고, 이유는 "필요함", "이미 알바생 화면에 있는 할 일과 중복되지 않습니다"처럼 뭉뚱그린 말이었습니다.

**11/21 고친 것:** summary 칸 설명에 한도(한글 34자)를 미리 적고, 거절 문구에 지금 글자 수를 알렸습니다. 같은 입력으로 6번 돌려 5번 성공했습니다. 실패한 1번은 71자 → 43자로 줄였지만 34자에 못 미쳤습니다.

**남은 것:** 성공한 5번 모두 keep이었고, 이유는 "이미 알바생 화면에 있는 할 일: 없음"이나 카드 문장을 그대로 옮긴 말이었습니다. 위 5장의 아쉬운 문장도 팀장이 걸러 내지 못했습니다.

**정한 것 (2026-11-21):** 팀장을 없앴습니다([agent-structure.md](agent-structure.md) 5장). 팀장 평가 세트는 만들지 않습니다. 사원 결과는 모두 남고, 순서는 코드가 정하며, 영업 중 알림은 팀장 몫(최대 15초)만큼 빨라졌습니다.

## 7. 계획과 다르게 한 것

[agent-org-plan.md](agent-org-plan.md) 맨 위에도 적었습니다. 결정과 맞는지 봐 주세요. **11/21에 8줄 모두 코드와 맞는 것을 확인했습니다.**

| 무엇 | 계획 | 실제 | 이유 |
|---|---|---|---|
| 리뷰 교정 할 일의 출처 값 | `origin=negative_review` | `origin=review` (넣은 사원은 `source.by=negative_review`) | 이미 저장된 할 일을 고치지 않으려고 |

| 같은 할 일 묶기 | 바이그램 후보 → LLM | 거의 같은 글(0.9 이상, `proposals.py`의 `SAME_TEXT`)은 LLM 없이 묶음 | 시연 픽스처에서 같은 카드가 두 번 물어짐 |
| "늦어서 식었어요" | (정하지 않음) | 배달 지연으로 먼저 봄 → 교정 카드 없음 | 결정 7(배달 지연은 주문 기록 전까지 빼기)에 맞춤 |

# 사장님 확인 (사업자 심사, 목업)

가게를 고른 사람이 정말 그 가게 사장님인지 확인합니다. **확인(심사)이 끝나야 계정과 가게가 이어집니다.** 지금은 진짜 국세청이나 사람 심사 없이 목업으로 돌지만, 흐름과 규칙은 실제와 같은 모양으로 만들었습니다.

## 1. 왜 필요한가

- 지금까지는 아무 계정이나 아무 가게를 등록하면 그 가게의 사장님이 됐습니다. 먼저 등록한 사람이 가게를 차지해서, 사장님인 척하는 사람이 먼저 등록하면 진짜 사장님이 막힐 수 있었습니다.
- 사업자등록번호만으로는 확인이 안 됩니다. 번호와 대표자 이름은 영수증과 배달앱 가게 화면에 나와 있어 누구나 알 수 있습니다.
- 그래서 다른 서비스(네이버 스마트플레이스, 카카오맵 매장관리)처럼 **사업자등록증 + 국세청 확인 + 심사**를 거치게 했습니다.

## 2. 가입 흐름

```
우리 가게 찾기 → 이 가게가 맞나요? (가게만 등록) → 사장님 확인 → 심사 중 → 사장님 확인이 끝났어요 → 가게 정보 확인 → …
                                                                  └→ 보류: 까닭 + [다시 쓰기] (가게가 다르면 [가게 다시 찾기])
```

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 사장님 확인을 해 주세요 | `/start/owner-check` | 사업자등록번호(000-00-00000), 대표자 이름, 개업일자(2021.04.01), 사업자등록증 사진. 번호 검증 숫자·날짜 모양은 바로 알려 줌. **데모 테스트 모드면 "시험용 값 넣기"** |
| 확인하고 있어요 | `/start/owner-review` | 심사가 끝날 때까지 기다림 (서버 5초, 앱 안 목업 3초). 1.5초마다 결과를 다시 읽음 |
| 사장님 확인이 끝났어요 | 〃 | [다음] → 이 기기의 가게를 그 가게로 바꾸고 가게 정보 확인으로 |
| 보류 | 〃 | 까닭 제목·설명 + [다시 쓰기], 가게가 다르거나 이미 확인된 가게면 [가게 다시 찾기] |

- 진행 막대는 7칸이 됐습니다 (가게 찾기, 가게 확인, **사장님 확인**, 가게 정보, 리뷰, 출근·퇴근, 알림).
- 설정 "우리 가게 다시 찾기"도 같은 확인을 거칩니다. 승인되면 설정으로 돌아가며 "우리 가게를 바꿨어요".
- 심사가 끝날 때까지는 앱으로 들어가지 않습니다. 중간에 나가면 다음 로그인에서 가게 찾기부터 다시 합니다.

## 3. 심사 규칙 (`server/app/modules/owner_check/review.py`)

신청할 때 바로 거르는 것 (심사로 보내지 않음, 422):

| code | 언제 |
|---|---|
| `INVALID_BUSINESS_NO` | 10자리가 아니거나 마지막 검증 숫자가 틀림 |
| `OWNER_NAME_REQUIRED` | 대표자 이름이 비었음 |
| `INVALID_OPENED_ON` | 없는 날짜이거나 앞으로의 날짜 |
| `DOCUMENT_REQUIRED` | 사업자등록증 사진이 없음 |

심사 시간이 지난 뒤 정하는 결과 (위에서부터 차례로 봄):

| 결과 | code | 화면 제목 |
|---|---|---|
| 보류 | `NTS_NOT_FOUND` | 국세청에 없는 번호예요 |
| 보류 | `NTS_MISMATCH` | 적은 내용이 달라요 (대표자 이름·개업일자가 틀림) |
| 보류 | `CLOSED` | 폐업한 사업자예요 |
| 보류 | `SUSPENDED` | 휴업 중인 사업자예요 |
| 보류 | `OTHER_STORE` | 다른 가게의 사업자예요 |
| 보류 | `TAKEN` | 이미 확인된 가게예요 |
| **승인** | | 계정과 가게를 잇는다 (등록 기록 `owners`) |

- 국세청 확인은 진짜 서비스(공공데이터포털 "국세청 사업자등록정보 진위확인 및 상태조회")와 같은 모양으로 흉내 냅니다(`mock_nts.py`). 상태조회는 번호만으로 사업 상태를, 진위확인은 번호·대표자·개업일자가 맞는지만 알려 줍니다.
- "고른 가게와 같은가"는 진짜로는 사업자등록증 사진의 상호·주소를 읽어 맞춰 봅니다. 목업은 시험용 자료에 적어 둔 가게(네이버 플레이스 id)로 맞춰 봅니다.
- 대표자 이름은 띄어쓰기를 무시합니다.
- 탈퇴하면 그 계정의 승인을 `withdrawn`으로 바꿉니다(기록은 남김). 그 가게는 다른 계정이 다시 확인받을 수 있고, 같은 아이디로 다시 가입하면 다시 확인받습니다.

## 4. 시험용 값 (`server/db/mock_business_registrations.json`)

모두 시험용으로 지은 값입니다. 데모 테스트 모드에서 "시험용 값 넣기"를 누르면 고른 가게에 맞는 값이 들어갑니다.

| 사업자등록번호 | 대표자 | 개업일자 | 상태 | 가게 | 결과 |
|---|---|---|---|---|---|
| `120-81-03450` | 김도나 | 2021.04.01 | 계속사업자 | 초옹장 (s005) | 초옹장이면 **승인** |
| `412-87-05567` | 김도나 | 2019.09.02 | 계속사업자 | 피플스클럽 (s004) | 피플스클럽이면 **승인** |
| `215-93-01277` | 김도나 | 2015.05.20 | 폐업자 | 없음 | 보류 (폐업) |
| `316-45-09829` | 김도나 | 2018.03.12 | 휴업자 | 없음 | 보류 (휴업) |

- 초옹장 번호로 피플스클럽을 고르면 "다른 가게의 사업자예요", 이름이나 개업일자를 바꾸면 "적은 내용이 달라요"를 볼 수 있습니다.
- `508-12-07344`는 모양은 맞지만 자료에 없는 번호라 "국세청에 없는 번호예요"가 나옵니다.
- 값을 더하려면 JSON에 한 줄 더 넣고 서버를 다시 켭니다. 번호는 검증 숫자 규칙을 지켜야 합니다 (`mock_nts.is_valid_number`).
- 앱 안 목업 모드(`EXPO_PUBLIC_USE_MOCK=true`, 서버 없음)는 모양만 맞으면 3초 뒤 승인합니다.

## 5. API

| | |
|---|---|
| `POST /api/owner_check` | `{store_id, owner_key, business_no, owner_name, opened_on: "YYYY-MM-DD", document}` → `{check_id, status: "reviewing", seconds_left, …}` |
| `GET /api/owner_check/{check_id}` | `{status: "reviewing" \| "approved" \| "held", reason_code, reason_title, reason_sub, business_no: "120-81-*****"}`. 승인되면 이때 계정과 가게를 잇는다 |
| `GET /api/owner_check/sample?store_id=` | 그 가게로 통과하는 시험용 값 |

- `POST /api/stores/register`는 이제 가게만 등록하고 **계정과 잇지 않습니다** (`owner_key`를 보내도 쓰지 않음).
- 기록: `db/app_data/registry.db`의 `owner_checks` 표. 사진 파일은 받지 않고 이름만 적습니다.
- 시험: `server/tests/modules/test_owner_check.py`

## 6. 진짜로 바꿀 때

- `mock_nts.py` → 공공데이터포털 국세청 API (인증키 필요, `status`·`validate`)
- 사업자등록증 사진 → 파일 받기 + OCR로 상호·주소 읽기 + 사람 심사 화면
- `REVIEW_SECONDS` 기다림 → 심사 담당자가 승인·보류를 누르는 관리 화면

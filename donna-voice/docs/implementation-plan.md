# 도나 v0.2.0 구현 계획

Figma `v0.2.0 : 음성처리` 확정안을 **새 앱**으로 구현하는 계획입니다. 기존 앱(`mobile/`, `frontend/`, `server/`)은 건드리지 않고, 이 폴더(`donna-voice/`) 안에서 프론트와 백엔드를 모두 새로 만듭니다.

> 기준: 2026-11-15
> 화면 기준: Figma 묶음 D · 확정안(D-01 ~ D-12), E · 시작, 로그인, 마이크 허용(E-01 ~ E-05)
> 백엔드 계약: [docs/v0.2.0-voice-agent-handoff.md](../../docs/v0.2.0-voice-agent-handoff.md)

---

## 1. 무엇을 만드나

매장을 운영하는 **사장님이 직접 쓰는 앱** 하나입니다. 판단 기준은 "기능이 많은가"가 아니라 "사장님이 장사하는 데 실제로 도움이 되는가"입니다.

- 말로 묻고 말로 듣습니다. 화면은 못 들었을 때 눈으로 확인하는 곳입니다.
- 휴대폰과 태블릿 비율 모두에서 씁니다 (반응형, 3장).
- 에이전트는 아직 연결하지 않습니다. 백엔드는 **목업**이고, 나중에 에이전트로 바꿔 끼울 수 있게 계약(API 모양)만 지킵니다.

## 2. 폴더와 주소

```
donna-voice/
  app/       프론트 (Expo, React Native Web)   http://localhost:8090
  server/    백엔드 목업 (FastAPI)             http://localhost:8100
  docs/      계획, 아직 못 정한 기능
```

기존 앱이 쓰는 주소(3000, 8000, 8082)와 겹치지 않습니다.

| 고른 것 | 이유 |
|---|---|
| Expo SDK 58 (기존 `mobile/`과 같은 버전) | 팀이 정한 방향(휴대폰·태블릿 앱으로 설치, 웹으로 확인)과 같고, 이 컴퓨터에서 이미 돌아가는 버전이라 설정 위험이 적음 |
| 화면 스타일은 `StyleSheet` + 토큰 파일 하나 | 간격 규칙(4·8·12·16·24)을 코드에서 그대로 강제하기 쉬움 |
| 탭은 직접 그린 메뉴바 | Figma의 "위·가운데·아래 자리가 어느 화면에서나 같다"를 지키려면 머리, 듣기 알약, 메뉴바를 한 틀에 고정해야 함 |
| 백엔드는 FastAPI | 팀의 기존 서버와 같은 언어. 인수인계 문서의 계약을 그대로 구현 |

## 3. 반응형

Figma에는 휴대폰(375 × 812) 화면만 있습니다. 태블릿 배치는 아래 규칙으로 새로 정합니다. **위(날짜·매장·소리)와 맨 아래(메뉴바)는 어느 크기에서나 같습니다.**

**도나와 듣기 알약은 홈에만 있습니다.** 일정, 매출, 설정은 눈으로 보는 화면이라 마이크가 필요 없고, 마이크가 켜져 있든 꺼져 있든 알릴 것이 없습니다. 듣는 것도 홈에서만 합니다.

| 너비 | 이름 | 배치 | 글자 |
|---|---|---|---|
| 600 미만 | 휴대폰 | Figma 그대로. 한 줄기 | Figma 크기 |
| 600 ~ 899 | 태블릿 세로 | 한 줄기. 내용 폭은 최대 600, 가운데. 홈의 도나는 내용 아래 **남은 자리의 가운데**에 섬 | 한 단계 크게 |
| 900 이상 | 태블릿 가로 | 두 칸. 홈은 왼쪽 칸 **가운데**에 도나와 듣기 알약, 오른쪽에 대화. 다른 탭은 카드를 두 칸으로 | 한 단계 크게 |

- **왜 태블릿은 글자를 키우나**: 태블릿은 주방 벽이나 카운터에 세워 두고 멀리서 봅니다. 휴대폰보다 보는 거리가 멉니다.
- **왜 가로에서는 두 칸인가**: 가로로 긴 화면에 한 줄기를 두면 카드가 지나치게 넓어지고 아래가 잘립니다. 도나와 듣기 알약을 왼쪽에 세우면, 휴대폰에서 내용이 길 때 도나를 숨기던 문제도 없어집니다.
- **태블릿에서 도나의 자리**: 휴대폰에서는 도나가 듣기 알약 바로 위(화면 아래)에 붙어 있지만, 태블릿에서는 아래에 붙이지 않고 가운데에 둡니다.
- **메뉴바**: 어느 크기에서나 맨 아래에 둡니다.

| 글자 | 휴대폰 | 태블릿 |
|---|---|---|
| 큰 제목 (display) | 28 / 38 | 34 / 46 |
| 제목 (title) | 22 / 31 | 28 / 38 |
| 본문 (body) | 18 / 28 | 22 / 32 |
| 작은 제목 (label) | 15 / 22 | 18 / 26 |
| 아주 작은 글 (small) | 14 / 20 | 16 / 22 |
| 화면 양옆 여백 | 24 | 32 |

확인하는 크기: 375 × 812(휴대폰), 768 × 1024(태블릿 세로), 1024 × 768(태블릿 가로).

## 4. 화면

| 화면 | Figma | 내용 |
|---|---|---|
| 시작 | E-01 | 도나 소개와 시작 버튼 |
| 로그인 | E-02 | 시작 방법 고르기 (목업: 누르면 통과) |
| 마이크 | E-03 ~ E-05 | 마이크 부탁, 허용하지 않았을 때 |
| 홈 (대화) | D-01 ~ D-12 | 준비해 둔 것, 브리핑 5단계, 다시 듣기, 화면으로 보기, 못 알아들음 |
| 일정 | 없음 (새로 정함) | 달력과 고른 날: 언제 무슨 일이 잡혀 있는지, 준비할 것, 올릴 답글, 그날 한 것 |
| 매출 | 없음 (새로 정함) | 오늘 지금까지, 이번 주, 잘 팔린 메뉴 |
| 설정 | 없음 (새로 정함) | 소리, 마이크, 아쉬운 리뷰 바로 답하기, 브리핑 준비 시각, 로그아웃 |

Figma에 없는 세 탭은 "사장님이 그 탭에서 알고 싶은 것 하나"에서 출발합니다.

| 탭 | 사장님이 알고 싶은 것 | 넣는 것 | 넣지 않는 것 |
|---|---|---|---|
| 일정 | 언제 무슨 일이 잡혀 있나, 뭘 준비하나, 도나가 언제 무슨 답글을 올리나, 뭘 했나 | **갤럭시 기본 캘린더(One UI 4부터)를 그대로 따름**. 휴대폰·태블릿 세로는 캘린더의 "목록 보기": 이번 주 7칸 / 이번 달, 일이 있는 날은 날짜 칸이 옅게 참, 날짜를 누르면 아래에 날짜·날씨 한 줄과 "시각 | 할 일" 목록(하루 종일인 것은 꼬리표). 태블릿 가로는 캘린더의 "월간 보기"(가게 벽의 종이 달력): 한 달이 왼쪽을 채우고 날짜 칸 안에 일정의 짧은 이름(단체 12명, 한국시리즈, 비, 답글), 오른쪽에 고른 날의 목록. 그 아래는 준비할 것 한 줄, 오늘 한 것(접어 둠), 지난 날은 그날 한 것. 색은 갈색 하나 | 붐빔 예상, 새로 만든 그림, 큰 한마디, 진행 띠, 예상 매출, 답글 전체 목록 |
| 매출 | 오늘 장사가 어떤가, 뭐가 잘 팔리나 | 오늘 지금까지와 지난주 같은 요일 비교, 이번 주 요일별 막대, 잘 팔린 메뉴 3개 | 달별·시간대별·채널별 표, 원가와 이익 |
| 설정 | 도나에게 맡긴 것을 끄고 켤 수 있나 | 소리, 마이크, 아쉬운 리뷰 바로 답하기, 브리핑 준비 시각, 로그아웃 | 알림 시각 세 번, 시간대 나누기, 개발자 도구 |

개발자 대시보드는 사장님이 쓰는 것이 아니라서 앱에 넣지 않습니다. 목업 데이터를 넣고 시각을 옮기는 것은 백엔드의 `/v1/dev/*`로 합니다.

## 5. 음성

| 하는 일 | 웹 | 휴대폰·태블릿 앱 |
|---|---|---|
| 듣고 글자로 바꾸기 (STT) | 브라우저의 Web Speech API | 아직 안 함 (`docs/open-features.md`) |
| 소리 내어 읽기 (TTS) | 브라우저의 speechSynthesis | 아직 안 함 |
| 칩 누르기 | 됨 | 됨 |

음성 부분은 `src/lib/voice.ts` 한 파일 뒤에 숨깁니다. 나중에 앱용 STT·TTS로 바꿔도 화면 코드는 그대로입니다. 브라우저가 음성을 지원하지 않으면 칩으로만 씁니다.

## 6. 순서

1. 백엔드 목업: `GET /v1/home`, `POST /v1/turn`, 설정, 이번 주, 매출, 개발용 API
2. 프론트 뼈대: 토큰, 글자, 아이콘, 화면 틀(머리 / 대화 / 도나·알약 / 메뉴바)
3. 시작, 로그인, 마이크
4. 홈과 브리핑
5. 이번 주, 매출, 설정
6. 태블릿 배치
7. **검토와 개선 3번**: 매번 사장님 입장에서 써 보고, 부족한 것을 고칩니다. 결과는 7장에 적습니다.

## 7. 검토 기록

구현을 마친 뒤 세 번 검토하고 고쳤습니다. 매번 사장님 입장에서 써 보는 것을 기준으로 했습니다. 확인한 크기는 375 × 812, 360 × 640, 768 × 1024, 1024 × 768입니다.

### 1회차: 화면이 규칙대로 놓였나

| 찾은 것 | 고친 것 |
|---|---|
| 태블릿 세로에서 날짜와 매장 이름이 아래 내용(게이지바, 카드)과 왼쪽 선이 어긋남 | 머리 줄도 내용과 같은 폭으로 가운데에 둠 |
| 웹에서 날짜가 화면 맨 위에 붙음 | 위 여백을 24로 |
| 도나가 말을 시작할 때 첫 문장에는 짧은 글이 없어, 두 번째 문장에서 카드가 한 줄 밀림 | 첫 문장부터 짧은 글 자리를 채워 둠 |
| 매출 탭에서 도나의 말과 카드가 같은 숫자를 두 번 보여 줌 | 카드는 "어제 / 지난주 같은 요일"을 나란히 견주도록 바꿈. 이번 주 합계와 지난주 대비도 한 줄로 더함 |
| 이번 주 탭의 한 줄 요약이 "요" 한 글자만 다음 줄로 넘어감 | 문장을 줄임 |
| 설정 아이콘이 무엇인지 알아보기 어려움 | 손잡이가 둥근 조절 막대 모양으로 바꿈 |
| 브리핑이 끝난 뒤 처음 화면으로 돌아갈 길이 "그만"뿐 | 홈에서 홈 탭을 다시 누르면 준비해 둔 것으로 돌아감 |
| 브라우저가 목소리를 내지 못할 때 한 문장에 4초 넘게 멈춤 | 읽기를 시작하지 못하면 글 읽을 시간만큼만 기다림 |

### 2회차: 흐름이 끝까지 이어지나

브리핑 5단계, 허락 묻기, 다음 날 시나리오(도나가 답한 리뷰), 화면으로 보기, 읽어 줘, 돌아가기, 끝, 못 알아들음, 도나에게 한 말이 아님, 말로 탭 옮기기, 서버가 꺼졌을 때를 모두 돌려 봤습니다.

| 찾은 것 | 고친 것 |
|---|---|
| 한글이 낱말 가운데서 줄이 바뀜 ("다 / 음 주문은") | 띄어쓰기에서만 줄을 바꿈 |
| 도나가 다시 나타날 때 그림이 잠깐 빔 | 도나를 늘 그려 두고, 자리가 없을 때만 안 보이게 함 |
| 다른 탭에서 홈으로 돌아가는 말이 없음 | "홈"이라고 하면 준비해 둔 것으로 돌아감 |
| 서버가 꺼지면 머리 줄의 날짜가 빔 | 이 기기의 날짜를 보여 줌 |

### 3회차: 손을 못 쓰는 사장님에게 맞나

| 찾은 것 | 고친 것 |
|---|---|
| **작은 휴대폰(360 × 640)에서 도나가 마지막에 말하는 줄과 칩이 화면 아래로 잘림.** 손을 못 쓰는 사장님은 화면을 밀 수 없음 | 도나가 읽는 만큼 화면이 저절로 따라 내려가고, 다 읽으면 맨 아래 칩이 보임 |
| 위와 같은 경우 도나의 말(첫마디)이 화면 위로 밀려 올라감 | 고치지 못함. `open-features.md` 2장에 적음 |
| 실제 마이크로 말해 보지 못함 | 개발 환경에 마이크가 없어 확인하지 못함. `open-features.md` 1장에 적음 |

### 4회차: 사용자 피드백 (2026-11-15)

| 받은 말 | 고친 것 |
|---|---|
| 이번 주에는 오늘 뭘 했는지, 남은 게 뭔지, 이번 주 예정, 예약된 리뷰, 과거에 한 일, 브리핑을 듣고 한 일이 들어가야 한다 | 이번 주 탭을 다섯 묶음으로 다시 만듦: 오늘 한 것, 아직 남은 것, 이번 주 예정, 예약한 답글, 지난 일. 브리핑을 끝까지 듣거나 허락하면 "오늘 한 것"에 사장님이 한 일로 적히고 "아직 남은 것"에서 빠짐 |

### 5회차: 사용자 피드백 (2026-11-15)

| 받은 말 | 고친 것 |
|---|---|
| 이번 주 탭을 열면 오늘 한 것과 남은 것만 보인다. 예전처럼 이번 주나 이번 달 상황을 볼 수 있어야 한다. 캘린더를 넣어 보자 | 맨 위에 달력을 둠. "이번 주"와 "이번 달"을 바꿔 볼 수 있고, 날짜를 누르면 그날의 내용이 아래에 나옴. 오늘 한 것과 남은 것은 오늘을 골랐을 때의 내용으로 들어감. 태블릿 가로에서는 왼쪽에 달력, 오른쪽에 고른 날 |

### 6회차: 사용자 피드백 (2026-11-15)

| 받은 말 | 고친 것 |
|---|---|
| 색감 때문인지 늘어져 보이고, 다시 들어가거나 매일 쓰고 싶은 느낌이 안 든다 | 바쁜 날은 달력 칸에 따뜻한 색을 채움. 고른 날은 색이 든 카드로: 바쁜 날은 따뜻한 색, 평소 같은 날은 초록, 지난 날은 종이색. 카드마다 도나가 다른 모습으로 나오고, 오늘은 한 만큼 채워지는 띠가 있음. 색은 새로 만들지 않고 있던 토큰을 더 넓게 씀 |
| 필요한 것은 다 있는데 봐야 할 것이 너무 많아 부담스럽다 | 한 번에 보는 것을 달력과 고른 날 하나로 줄임. 늘 떠 있던 "예약한 답글 전부"와 "지난 일" 묶음을 없애고(달력에서 그날을 누르면 나옴), 한 줄 요약 글과 긴 이유 목록을 덜어 냄. "오늘 한 것"은 접어 둠. 오늘의 이유는 "아직 남은 것"과 겹쳐서 뺌 |
| 이번 주와 이번 달을 다 보여 주는데 탭 이름이 "이번 주"인 것은 이상하다. "달력"보다는 기능을 말하는 이름이 좋다. 달력이라는 것은 아이콘이 이미 알려 준다 | 탭 이름을 **일정**으로 바꿈 |

### 7회차: 사용자 피드백 (2026-11-15)

| 받은 말 | 고친 것 |
|---|---|
| 색이 너무 많아서 보기 불편하다 (일정 탭) | 일정 탭의 색을 **둘**로 줄임. 갈색(도나, 고른 것, 한 것, 답글 점)과 따뜻한 색(바쁨)뿐. 초록·파랑을 없앰: 평소 같은 날과 지난 날의 카드는 흰 카드로, 체크와 아이콘 칸과 답글 점과 이유 꼬리표는 갈색으로. 바쁜 날만 달력 칸과 고른 날 카드에 같은 따뜻한 색이 들어감(같은 색은 같은 뜻). 날의 구분은 색 대신 도나의 모습과 글로 함. 홈의 브리핑 카드는 그대로 둠 (`Cards`의 `mono`는 일정 탭에서만 켬) |
| 태블릿의 이번 주는 빈 공간 때문에 덜 만든 앱처럼 보인다 | 태블릿 가로의 이번 주가 왼쪽 칸을 세로로 다 쓰게 함 (처음에는 하루 한 줄 목록으로 만들었으나 아래 말로 그림이 됨). 범례까지 1024 × 768 한 화면에 들어오고, 화면이 더 길면 칸이 그만큼 커짐. 한 달은 칸 높이를 키워(56) 여섯 주인 달도 한 화면에 참. 어느 크기든 이번 주부터 열림 |
| (하루 한 줄 목록을 보고) 글이 너무 많아서 보기 싫을 것 같다. 시각화하자 | 목록을 **그림**으로 바꿈. 가로는 요일, 세로는 점심·저녁·밤이고, 바쁜 때는 칸이 따뜻한 색으로 진함(보통은 옅은 갈색, 한가는 빈 칸, 지난 날은 흐리게). 글은 요일과 "점심·저녁·밤" 세 마디, 범례뿐. 날씨는 아이콘으로만. 요일이 가로로 놓이는 것은 휴대폰의 7칸, 한 달 달력과 같음. 이유와 준비할 것은 날짜를 눌렀을 때 오른쪽에 나옴. 이 그림을 위해 서버가 지난 날에도 `dayparts`를 줌 |
| 왜 여기서 바쁜지 안 바쁜지를 보여 주나. 사장님에게 꼭 필요한가. 더 필요한 것은 없나 | **붐빔 표시를 일정 탭에서 모두 뺌** (바쁜 날 색, "저녁이 바빠요", 점심·저녁·밤 칩, 바쁨 그림). 예전 앱의 붐빔 예상을 따져 보지 않고 가져온 것이었음. 사장님은 자기 가게가 언제 바쁜지 이미 알고, "바쁨"은 확인할 수 없는 추측이며, 그것만 보고 할 행동이 없음. 대신 **날짜와 시각이 있는 사실**을 보여 줌: 그날 잡힌 일(행사, 경기, 단체 예약, 비), 그래서 준비할 것 한 줄, 그날 올릴 답글. 태블릿 그림은 요일 × 오전·오후·저녁 칸에 잡힌 일과 답글이 아이콘으로 놓이고(비는 하루 종일이라 세 칸 모두), 일이 없는 칸은 비어 있음. 큰 한마디는 사실로("경기가 있어요", 둘 이상이면 "일이 여러 가지 있어요": 휴대폰에서도 한 줄). 바쁠 것이라는 말은 준비할 것의 이유로만 남음. 따뜻한 색(바쁨)이 빠져 일정 탭의 색은 갈색 하나 |
| (요일 × 오전·오후·저녁 아이콘 그림을 보고) 전혀 직관적이지 않다. 왜 이 방식을 골랐나. 외부 레퍼런스를 찾아 새로 만들라. 이걸 왜 봐야 하는지, 보고 뭘 느끼는지 모르겠다. Learnability를 고려하라 | 그림은 레퍼런스 없이 제가 새로 만든 표현이라, 사장님이 처음 보는 읽는 법을 배워야 했음. **사장님이 이미 매일 쓰는 달력을 그대로 따르도록 다시 만듦**. 레퍼런스: 삼성 캘린더 담당자의 One UI 4 캘린더 소개 글(삼성 멤버스, 2021-11-16). 거기서 가져온 것: "종이 달력"처럼 날짜를 가운데 크게, 배경색과 표시줄을 걷어 냄, 목록 보기는 일이 있는 날짜만 표시하고 누르면 그날 일정을 목록으로, 일정마다 시작 시각을 캘린더 색으로 강조, 오늘은 지나간 일정이 빠지고 남은 것만. 태블릿 가로는 같은 캘린더의 월간 보기(칸 안에 일정 이름). 화면이 답하는 것: "이번 주에 내가 챙길 날이 언제지?" 사장님이 느낄 것: 행사, 경기, 비, 단체 예약, 도나가 올릴 답글이 내가 적지 않아도 달력에 이미 적혀 있다. 그래서 그림, 큰 한마디("일이 여러 가지 있어요"), 도나 그림, 진행 띠를 뺌. 태블릿 가로는 한 달 안에 이번 주가 보이므로 이번 주/이번 달을 고르지 않음. 서버는 일정마다 달력 칸에 적을 짧은 이름(`short`)을 줌 |

### 8회차: 호출어 결정 (2026-11-16)

| 말씀 | 고친 것 |

| "도나야"로 부르게 해 주세요 (operating-scenarios.md 5장 1번) | 부르지 않은 말은 앱이 흘려보냄 (화면에 적지 않고 서버로 안 보냄). "도나야, …"는 부르는 말을 떼고 `addressed: true`로 보냄. "도나야"만 부르면 "네" 하고 8초 동안 들음. 브리핑 중과 도나가 답한 뒤 8초는 부르지 않아도 들음. 듣기 알약: 평소 "“도나야” 하고 불러 주세요", 부른 뒤 "듣고 있어요". 불러야 하는 때의 칩에는 "도나야, "를 붙여 보여 줌. 마이크 켜는 화면과 설정의 설명도 같은 말로 바꿈. 서버 목업은 부른 말을 `ignore` 하지 않음 |

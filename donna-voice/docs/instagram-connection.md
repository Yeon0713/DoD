# 인스타 계정 연결 방식 조사

2026-11-16. [operating-scenarios.md](operating-scenarios.md) 5장 6번(계정 연결)과 10번(리스토리)을 정하기 위한 조사입니다. 메타 개발자 문서를 직접 읽어 확인한 것과 확인하지 못한 것을 나눠 적었습니다.

## 1. 결론

| 하려는 것 | 공식 방식으로 되나 | 근거 |
|---|---|---|
| 피드에 사진 여러 장 올리기 (매출 순위 피드) | **됨** | 콘텐츠 게시 API. 한 게시물에 사진·영상 20개까지 |
| 글에 네이버 플레이스 주소 넣기 | 됨 (글자로 들어감. 인스타 글의 주소는 눌러지지 않음) | 캡션은 자유 글 |
| 손님이 매장을 태그해 스토리를 올린 것 알기 | **됨** | 스토리 멘션 웹훅. 올린 즉시 알림이 옴 |
| 그 스토리를 매장 계정이 리스토리 | **공식 기능에 없음** | 스토리 멘션 문서, 게시 API 문서 어디에도 리스토리가 없음 |
| 매장 계정이 자기 스토리 올리기 | 됨 | 게시 API의 `STORIES`. 링크·투표·위치 스티커는 안 됨 |
| 비밀번호를 받지 않고 연결 | **됨** | 인스타그램 로그인. 페이스북 페이지도 필요 없음 |

**권하는 방식**: 아이디·비밀번호를 받지 않고 **인스타그램 공식 로그인**으로 연결합니다. 피드 게시는 완전 자동, 리스토리는 "도나가 알려 주고 사람이 두 번 누르기"로 합니다 (4장).

## 2. 아이디·비밀번호로 봇이 로그인하는 방식 (회의 안)

| 항목 | 내용 |
|---|---|
| 약관 | 인스타그램 이용 약관은 다른 사용자의 로그인 정보를 요청·수집·사용하는 것을 금지하고, 허락 없이 자동화된 방식으로 계정을 만들거나 정보를 모으는 것을 금지합니다. 우리가 사장님 비밀번호를 받는 것 자체가 여기에 걸립니다 |
| 일어나는 일 | 자동화로 보이는 동작이 잡히면 좋아요·팔로우·메시지가 하루 이틀 막히고, 비밀번호를 바꾸라는 요구가 옵니다. 되풀이되면 계정이 정지됩니다 (기간은 2차 자료 기준) |
| 2단계 인증 | 켜 둔 계정은 봇이 로그인하지 못합니다. 낯선 곳(서버)에서 로그인하면 본인 확인이 뜹니다 |
| 보관 책임 | 사장님들의 비밀번호를 우리 서버가 갖고 있어야 합니다. 새면 매장 계정이 통째로 넘어갑니다 |
| 사장님에게 주는 인상 | AI를 못 미더워하는 사장님에게 "비밀번호를 알려 주세요"는 가장 넘기 어려운 요청입니다 |

매출을 올리려고 만든 통로(매장 계정)를 잃을 수 있는 방식이라 권하지 않습니다.

## 3. 공식 방식: 인스타그램 로그인

### 3-1. 사장님이 하는 일

| 순서 | 하는 일 | 걸리는 시간 |
|---|---|---|
| 1 | 인스타 계정을 프로페셔널 계정(비즈니스)으로 바꿈. 인스타 앱 설정에서 무료로 바꿀 수 있음 | 1분쯤. 도나가 화면으로 안내 |
| 2 | 도나 설정에서 "인스타 연결"을 누르면 인스타 화면이 뜨고, 거기서 로그인하고 "허용"을 누름 | 1분쯤 |

비밀번호는 인스타 화면에만 넣습니다. 도나는 비밀번호를 보지 못하고, 대신 60일짜리 허가증(토큰)을 받습니다. 도나가 기한 전에 알아서 늘립니다. 페이스북 페이지는 필요 없습니다.

### 3-2. 우리가 준비할 것

| 항목 | 내용 |
|---|---|
| 메타 앱 | 메타 개발자 사이트에 앱을 만들고 인스타그램 제품을 붙임 |
| 권한 | 게시: `instagram_business_basic`, `instagram_business_content_publish`. 스토리 멘션 받기: 메시지 권한(`instagram_business_manage_messages`)과 웹훅 |
| 시범 운영 | **심사 없이 바로 됨.** 앱에 역할(테스터)로 넣은 계정은 표준 접근으로 쓸 수 있음. 시범 매장 몇 곳은 이 방식으로 시작 |
| 정식 서비스 | 우리가 관리하지 않는 계정에 쓰려면 고급 접근이 필요하고, **앱 심사와 사업자 인증**을 거쳐야 함. 심사 기간은 메타가 밝히지 않음 (2차 자료로는 2~4주, 사업자 인증이 10일 넘게 걸렸다는 글도 있음). 미리 신청해야 함 |
| 이미지 | JPEG만 됨. 메타가 주소로 가져가므로 **누구나 열 수 있는 주소**에 올려 두어야 함 (도나 서버가 이미지를 만들어 공개 주소로 내놓아야 함) |
| 비율과 크기 | **세로 4:5, 1080×1350 px로 만든다** (피드에서 가장 널리 쓰는 세로형). 다른 길: 3:4 1080×1440 (최근 휴대폰 카메라 비율, 최대 세로), 1:1 1080×1080 (프로필 격자와 같음), 가로 1.91:1 1080×566. 여러 장 게시물은 넉 장 모두 같은 비율로 만든다. 메뉴 사진(가로 3:2)은 가운데를 잘라 4:5로 맞춘다 |
| 한도 | 계정마다 24시간에 게시 50~100개 (문서 안에서도 숫자가 다름). 한 달에 한 번 올리는 데는 문제없음 |
| 안 되는 것 | 필터, 쇼핑 태그, 스토리의 링크·투표·위치 스티커 |

### 3-3. 매출 순위 피드가 올라가는 순서

1. 도나가 이번 달 가장 많이 나간 메뉴 1, 2, 3의 이미지(JPEG, 세로 4:5 1080×1350)와 글을 만든다.
2. 브리핑에서 사장님에게 보여 주고 "올릴까요?"를 묻는다.
3. "올려"라고 하면 이미지마다 게시 준비물(컨테이너)을 만들고, 묶어서 한 게시물로 올린다.
4. 올라간 게시물 주소를 받아 "오늘 한 것"에 적는다.

## 4. 리스토리: 세 가지 길

손님이 매장을 태그해 스토리를 올리면 웹훅이 옵니다. 알 수 있는 것은 **누가 올렸는지와 스토리 이미지 주소**입니다. 올린 손님 계정이 공개 계정이어야 오고, 비공개 계정은 매장 계정을 팔로우하고 있을 때만 옵니다. 스토리는 24시간 뒤 사라지고 주소도 그때 닫힙니다. 메타는 그 이미지를 우리 서버에 저장하지 말라고 합니다.

| 길 | 내용 | 자동인가 | 걱정 |
|---|---|---|---|
| **가 (추천)** 알려 주고 사람이 누르기 | 도나가 "손님 한 분이 스토리에 올려 주셨어요"를 알바생 TODO와 사장님 화면에 올림. 알바생이 서비스를 내고, 사장님이나 알바생이 인스타 앱의 DM에서 "내 스토리에 추가"를 누름 (두 번 누르기) | 알아채기는 자동, 리스토리는 사람 | 사람이 눌러야 함. 대신 손님 태그가 그대로 붙은 진짜 리스토리가 됨 |
| 나. 도나가 감사 스토리를 올림 | 손님 스토리를 다시 올리는 대신, 도나가 만든 이미지("오늘 스토리 올려 주신 손님들 감사합니다")를 매장 스토리에 올림 | 완전 자동 | 손님 사진이 들어가지 않음. 회의에서 뜻한 리스토리와 다름 |
| 다. 봇이 DM 창에 들어가 리스토리 (회의 안) | 2장의 아이디·비밀번호 방식 | 완전 자동 | 2장의 걱정 전부 |

가 안이 좋은 이유는 "서비스는 누가 내나"(5장 10번)가 같이 풀리기 때문입니다. 웹훅이 오면 도나가 알바생 TODO에 "스토리 올려 주신 손님께 서비스 드리기"를 넣습니다.

**확인하지 못한 것**

- 웹훅으로 받은 손님 스토리 이미지 주소를 그대로 매장 스토리 게시에 넘길 수 있는지. 기술로 되더라도 손님 태그가 붙지 않고, 손님의 사진을 허락 없이 새 게시물로 올리는 것이 되어 권하지 않습니다.
- 스토리 멘션에 도나가 감사 DM을 자동으로 답할 수 있는지. 메시지 API로 될 것으로 보이지만 문서에서 직접 확인하지 못했습니다.
- 앱 심사가 실제로 얼마나 걸리는지.

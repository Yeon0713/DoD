# 가입 흐름 바뀐 점: 매장 등록, 리뷰 불러오기, 데모 테스트 모드

팀원이 **가입 흐름과 매장 데이터가 어떻게 바뀌었는지** 한 번에 알 수 있게 정리한 문서입니다.
전체 구조(앱 · 서버 · DB · 분석)는 [how-frontend-server-db-analysis-connect.md](how-frontend-server-db-analysis-connect.md) 를 먼저 보세요.

> 기준: 2026-11-12 · 브랜치 `jheroorehj/fix-integration` · 정리: 영웅

## 1. 한눈에 보기

| 바뀐 것 | 전 | 지금 |
|---|---|---|
| 내 가게 정하기 | 네이버로 로그인하면 DB 가게(s001)가 바로 "사장님 가게"가 됨 | **네이버 지도에서 가게를 검색해 고르고 "이 가게가 맞나요?"를 확인한 뒤 등록**. 네이버 로그인만으로는 누가 어느 가게 주인인지 알 수 없기 때문 |
| 가게 정보 | DB 목업 가게 정보만 | 등록할 때 **네이버 지도 가게 화면을 한 번 읽어(크롤링) DB에 저장**. 평소에는 DB를 쓰고, 사장님이 원할 때만 다시 읽음 |
| 리뷰 | 가입하면 DB 리뷰가 그대로 | 가입 중 **"리뷰 불러오기" 단계**: 배민, 네이버, 쿠팡이츠 버튼을 각각 누름. 지금은 3초 로딩 뒤 목업 리뷰가 들어감 |
| 주문·매출 | 목업 가게만 있음 | 등록한 가게에 **우리 전용 목업 주문·매출·알바**를 그 가게 영업시간과 메뉴대로 만들어 넣음 (팀 목업 생성기와 따로, 기존 DB 는 안 건드림) |
| 알림 시간 | 장사 시간으로만 계산 | 그 전에 **출근·퇴근 예정 시간**을 받고(기본 = 여는·닫는 시간), 장사 시간·브레이크·출퇴근으로 계산. **알림 추가** 가능 |
| 네이버 로그인 | 앱 안에서 흉내만 냄 | **데모 테스트 모드**에서는 서버의 로그인 흐름(OAuth와 같은 순서)을 탐. 네이버 앱 키가 없으면 **임시 네이버 로그인 화면**(테스트 아이디·비밀번호)으로 감 |

## 2. 새 가입 흐름 (데모 테스트 모드)

```
시작 화면 ─ 오른쪽 위 메뉴(☰) › 데모 테스트 모드 켜기
   │
   ▼
네이버로 시작하기 ──▶ 임시 네이버 로그인 (dona_test1~3 / dona1234)
   │                    ※ 서버에 NAVER_LOGIN_CLIENT_ID/SECRET 이 있으면 진짜 nid.naver.com 으로 감
   ▼
① 우리 가게 찾기  (/start/store)        가게 이름 검색 → 네이버 지역 검색 결과 + 지도
   ▼
② 이 가게가 맞나요? (/start/store-confirm)  네이버 지도에서 읽은 주소·요일별 영업시간·브레이크·메뉴·리뷰 수
   │   "네, 우리 가게예요" → 서버가 DB에 등록 (계정과 가게를 이어 둠, 다음 로그인부터 바로 이 가게)
   ▼
③ 가게 정보 확인 (/start/naver-confirm)   장사 시간 고치기, 메뉴·사진 고치기는 네이버 스마트플레이스를 열어 줌
   ▼
④ 리뷰 불러오기 (/start/reviews)        배민 / 네이버 / 쿠팡이츠 각각 "불러오기" (3초 로딩 → 목업 리뷰)
   │   안 불러온 곳이 있는데 "다음"을 누르면:
   │   "○○ 리뷰 데이터를 불러오지 않았어요. 리뷰 데이터를 먼저 불러올까요?" [먼저 불러올게요] [불러오지 않고 넘어갈게요]
   ▼
⑤ 출근·퇴근 시간 (/start/work-hours)   기본은 여는·닫는 시간, 10분 단위로 고침
   ▼
⑥ 알림 시간 (/start/notify-time)  출근 10분 뒤 / 브레이크 시작 30분 뒤 / 퇴근 30분 전. "알림 추가하기"로 더 받을 시각을 넣음
   ▼
⑦ 알림 켜기 → 홈
```

- 데모 테스트 모드를 끄면 예전처럼 서버 기본 가게(s001)로 가는 흐름입니다 (팀 개발용).
- 휴대폰 번호로 시작해도 ① 가게 찾기부터 같습니다.
- 설정 › "우리 가게 다시 찾기"도 ①②를 거쳐 가게를 바꿉니다.

## 3. 매장 등록: 어디서 무엇을 가져오나

| 단계 | 쓰는 것 | 공식 API? | 가져오는 것 |
|---|---|---|---|
| 가게 검색 | NAVER API HUB 지역 검색 `/search/v1/local` (서버 `.env` 의 `NAVER_API_HUB_*`) | 공식 | 상호, 업종, 주소, 좌표 (최대 5곳) |
| 지도 그림 | NCP Maps Static Map `/map-static/v2/raster` (`NAVER_MAPS_*`) | 공식 | 검색 결과와 고른 가게에 핀을 찍은 지도 그림. 서버가 대신 받아 앱에 줌 (앱은 키를 모름) |
| 가게 id 찾기 | 네이버 모바일 검색 화면 | 크롤링 | 네이버 지도 가게 id (이름이 같고 0.5km 안) |
| 가게 상세 | 네이버 지도 모바일 가게 화면 `m.place.naver.com/place/<id>/home` 안의 데이터 | 크롤링 | 요일별 영업시간, 브레이크 타임, 휴무 안내, 메뉴(이름·가격·사진), 방문자 리뷰 수 |

> 크롤링은 **등록할 때 한 번**, 그리고 사장님이 **다시 불러오기**를 원할 때만 합니다. 네이버 화면 구조가 바뀌면 깨질 수 있고(그때는 "가게 정보를 읽지 못했어요"로 안내), 네이버 정책상 상시 수집에 기대기는 어렵습니다.

### 저장 위치

| 파일 | 내용 | git |
|---|---|---|
| `server/db/data/s101.db`, `s102.db` … | 등록한 가게 전용 파일. 기존 목업 가게(s001~s003)와 **같은 표 모양**. 가게 정보·메뉴가 들어가고, 리뷰는 리뷰 불러오기로 채움. 주문·알바는 없음 | 올리지 않음 (`.gitignore`) |
| `server/db/app_data/registry.db` | 등록 기록: `stores`(가게 id ↔ 네이버 가게 id, 읽은 정보 JSON), `owners`(로그인 계정 ↔ 가게), `review_platforms`(불러온 리뷰가 어느 플랫폼 것인지) | 올리지 않음 |

- 가게 파일은 s101 부터 붙입니다 (s001~s099 는 목업 가게 자리).
- **지호님 목업 생성기(`db/mock/generate.py`)를 다시 돌리면 `db/data/*.db` 가 모두 지워지므로 등록한 가게 파일도 지워집니다.** 그때는 다시 등록하면 됩니다 (등록 기록은 `app_data` 에 남아 있어도 파일이 없으면 무시).
- 기존 목업 가게 파일과 표 구조(`db/models.py`)는 **바꾸지 않았습니다**.

### 화면 모양
- 가게 찾기: 검색창(지우기 버튼), 춘천 지도와 예시 검색어, 찾은 가게를 **지도 위 번호 핀 ①②③ 과 같은 번호의 목록**으로 보여 줌. 고른 가게는 갈색 핀.
- 이 가게가 맞나요?: 화면 가로 끝까지 지도, 가게 이름과 업종, 도로명·지번 주소, 네이버 방문자 리뷰 수, **요일별 영업시간 표(오늘 강조)**, 브레이크, 휴무 안내, **메뉴 사진 가로 목록(이름·가격)**.
- 지도는 서버가 받아 주는 그림(Static Map)이다. 손가락으로 움직이는 지도(Web Dynamic Map)는 NCP 콘솔의 Maps 앱에 웹 서비스 주소(`http://localhost:8082` 등)를 등록해야 열린다 (지금은 인증 실패). 앱(iOS·Android)은 네이버 지도 앱 SDK 가 따로 필요하다.

## 4. 우리 전용 목업 주문·매출 (`server/app/modules/stores/demo_data.py`)

- 매장을 등록하면(`DEMO_STORE_DATA=true`, 기본 켜짐) 그 가게 파일에 주문, 주문 메뉴, 알바 3명, 근무를 넣는다. 이미 주문이 있으면 넣지 않는다.
- 기간: 등록한 날 70일 전 ~ 21일 뒤. 서버는 "지금" 이전 주문만 쓰므로 하루가 지나면 그날 매출이 쌓인다 (날짜 바꾸기 시험과 맞물림).
- 가게의 **실제 요일별 영업시간·브레이크·메뉴 가격**을 따른다: 평일 점심·저녁, 주말 점심만, 브레이크엔 주문 없음.
- 홀·배달, 배달 손님 번호로 **매주 단골 6명(같은 요일), 매달 단골 10명(4주 간격)**. 리뷰 불러오기 때 이번 주 좋은 리뷰 일부를 단골이 쓴 것으로 이어 단골 답글 일이 생긴다.
- **추운 날(공통 날씨 표 최고 10도 아래)**은 주문이 조금 늘고 라멘 같은 따뜻한 메뉴가 더 팔린다.
- 같은 가게는 늘 같은 데이터 (난수 씨앗 = 가게 id). 팀 목업 생성기(`db/mock/generate.py`)와 기존 가게 파일(s001~s003)은 쓰지도 고치지도 않는다.

## 5. 출근·퇴근 시간과 알림

- 가게 설정에 `work_hours`(출근·퇴근), `extra_slots`(더 넣은 알림 시각)를 더했다 (`StoreSettings`, `PATCH /api/settings`).
- 알림 세 시각 (`mobile/src/lib/hours.ts suggestSlots`): 출근 후 = 출근 10분 뒤(점심 바쁜 시간에 걸리면 출근할 때), 한가할 때 = 브레이크 시작 30분 뒤, 마감 전 = 퇴근 30분 전. 주말처럼 일찍 닫는 날은 마감 전 알림이 그만큼 당겨진다.
- 서버 검사: 알림은 "문 열기 1시간 전과 출근 시간 중 이른 때" ~ "마감과 퇴근 중 늦은 때" 사이, 세 알림은 바쁜 시간대에 걸리면 안 된다. 더 넣은 알림은 바쁜 시간이어도 된다.
- 더 넣은 알림은 앱이 매일 예약해 "남은 할 일이 있는지 확인해 보세요"로 알린다. **계획 엔진의 알림 묶음은 지금처럼 세 시각**이다 (할 일을 더 넣은 알림 시각에 나눠 담지는 않음).

## 6. 리뷰 불러오기

- 진짜로는 각 플랫폼 사장님 화면에서 크롤링해야 합니다 (아직 없음).
- 지금은 `server/app/modules/stores/review_import.py` 가 **목업 리뷰**를 만듭니다: 그 가게 메뉴 이름이 들어간 글, 최근 60일, 이번 주 좋은 리뷰 2건(토요일 답글 묶음), **불러온 날 새벽 불만 1건**(그날 첫 알림에 사과 답글이 생김). 배민·쿠팡이츠는 배달 지연, 네이버는 맛 불만.
- 같은 가게·같은 플랫폼은 늘 같은 리뷰가 나옵니다. 이미 불러온 플랫폼은 다시 넣지 않습니다.
- 가게 파일 `reviews` 표에는 플랫폼 칸이 없어서, 플랫폼은 `registry.db` 의 `review_platforms` 에 적고 **`read_store_db.read_reviews` 가 등록한 가게일 때만 붙입니다.** 목업 가게(s001~s003)는 예전 규칙(배달 주문이면 배민, 아니면 네이버) 그대로입니다.

## 7. 서버 API (새로 생기거나 바뀐 것)

| API | 하는 일 |
|---|---|
| `GET /api/naver/search?query=` | 가게 이름으로 네이버 지역 검색 |
| `GET /api/stores/map?lat&lng&level&markers=위도,경도;…&numbered&selected` | 지도 그림. `numbered` 면 핀에 1, 2, 3, `selected` 번 핀을 갈색으로 |
| `GET /api/stores/map-config` | 웹 지도(JavaScript)용 Client ID (NCP 에 웹 주소를 등록해야 동작) |
| `POST /api/stores/preview` `{name,address,lat,lng}` | 네이버 지도에서 가게를 읽어 "이 가게가 맞나요?"에 보여 줌 (저장 안 함) |
| `POST /api/stores/register` `{place_id, owner_key}` | 가게 등록 (DB 저장, 계정 연결). 같은 네이버 가게면 같은 가게 id 를 돌려줌 |
| `POST /api/stores/{store_id}/refresh` | 네이버 지도에서 다시 읽어 가게·메뉴 갱신 |
| `GET /api/stores/{store_id}/reviews` | 플랫폼별로 불러온 리뷰 수 |
| `POST /api/stores/{store_id}/reviews/import` `{platform}` | 리뷰 불러오기 (BAEMIN, NAVER, COUPANG). 지금은 목업 |
| `PATCH /api/settings` | `work_hours`, `extra_slots` 추가 |
| `GET /api/naver/place` | 응답에 `address`, `category` 추가. 등록한 가게면 네이버 지도에서 읽은 요일별 영업시간·브레이크·메뉴 사진을 돌려줌 |
| `GET /api/auth/naver/start` · `callback` · `result/{ticket}` | 네이버 로그인 (진짜 또는 임시). `result` 의 `store_id` 는 **그 계정으로 등록해 둔 가게**(없으면 null) |
| `GET/POST /api/auth/naver/mock/login` | 임시 네이버 로그인 화면 (네이버 앱 키가 없을 때만) |
| `POST /dev/clock?days=&hours=` | 개발용 서버 시계 앞당기기 (`DEV_CLOCK_ENABLED=true` 일 때만) |
| `POST /dev/reset` | 시험용 초기화: 등록한 가게 파일(s101 …)·등록 기록·불러온 리뷰·고친 설정·로그인 표를 지우고 시계를 되돌림. 목업 가게 s001~s003 은 그대로 (`DEV_CLOCK_ENABLED=true` 일 때만) |

앱은 로그인한 계정의 가게를 모든 요청에 `?store_id=` 로 붙입니다 (`mobile/src/lib/api.ts`).

## 8. 켜는 법과 설정

```bash
cd server
python run_dev.py        # 가상환경을 켠 뒤. Windows, Mac 같은 명령 (DEV_CLOCK_ENABLED=true, 8000번 포트)
```
```bash
cd mobile
npm run web              # http://localhost:8082
```

순서와 안 될 때 볼 것은 [README.md](../README.md) 2-7 에 있다. 앱은 연 주소와 같은 이름으로 서버를 부른다
(`http://localhost:8082` 로 열면 서버도 `http://localhost:8000`, `mobile/src/lib/server.ts`).

| 설정 (`server/.env` 또는 환경 변수) | 쓰임 |
|---|---|
| `NAVER_API_HUB_CLIENT_ID/SECRET` | 가게 검색 (이미 있음) |
| `NAVER_MAPS_CLIENT_ID/SECRET` | 지도 그림 (이미 있음) |
| `NAVER_LOGIN_CLIENT_ID/SECRET` | 진짜 네이버 로그인. **없으면 임시 네이버 로그인**. 도메인을 받아 developers.naver.com 에 앱을 등록하면 넣기 (Callback URL: `<서버 주소>/api/auth/naver/callback`) |
| `DEV_CLOCK_ENABLED` | 개발용 시계 앞당기기 |
| `DEMO_STORE_DATA` | 매장 등록 때 우리 전용 목업 주문·매출을 넣을지 (기본 true) |

- 앱: 시작 화면(또는 로그인 화면) ☰ › **데모 테스트 모드** 켜기. 같은 메뉴의 **초기화**는 서버의 등록 가게와 이 기기 기록을 지워 가게 찾기(지도)부터 다시 하게 한다. 데모 테스트 모드와 `?cursor=1` 은 초기화·로그아웃·서버 재시작에도 남는다 (`dona.keep.*`).
- 앱(예전 설명): 켜져 있으면 "알림이 꺼져 있어요" 띠를 띄우지 않습니다 (시험 브라우저는 알림을 켤 수 없음).
- 웹 시연 때 마우스 표시: 주소 끝에 `?cursor=1` (끄기 `?cursor=0`).
- **서버를 다시 켜면 앱 저장값(가입, 데모 모드 등)이 처음으로 돌아갑니다** (`/health` 의 boot_id). 등록한 가게와 불러온 리뷰는 DB 에 남습니다.

# 테스트 시나리오: 아쉬운 리뷰 → 답글 → 알바생 할 일 (닫힌 고리)

2026-11-18 작성. 팀 개선안(DONNA.pdf)에 맞춰 만든 기능을 이 문서의 번호대로 시험합니다. 코드와 테스트 이름이 이 번호를 따릅니다.

발표의 한 장면은 이렇습니다. 조리 중인 사장님에게 도나가 "방금 국물이 샜다는 리뷰가 왔어요. 사과 답글을 올리고, 알바생 할 일에 이중 실링을 넣을까요?" 하고 묻습니다. 사장님이 "응, 진행해" 한마디를 하면 리뷰 플랫폼에 답글이 올라가고, 알바생 휴대폰 할 일 맨 위에 교정 카드가 뜹니다.

숫자 셋: **30분**(아쉬운 리뷰 대응), **토요일 오전 11시**(평일 손님 리뷰 답글), **한마디 승인**(사장님이 하는 일).

| 묶음 | 무엇을 보나 | 확인 방법 |
|---|---|---|
| L | 고리가 끝까지 도는지 | pytest `server/voice/tests/test_loop_negative.py` |
| E | 사장님이 말로 고칠 수 있는지 | 같은 파일 |
| T | 대답이 없을 때 | 같은 파일 |
| P | 좋은 리뷰 답글 시각 | `test_positive_timing.py` (+ 기존 `test_scenario_a.py`, `test_v021_choongjang.py`) |
| S | 알바생 화면 | `test_staff_api.py` |
| G | 안전장치 (화면을 안 봐도 사고가 나지 않는 이유) | `test_loop_negative.py`, `test_compensation_guard.py`, `test_intent_rules.py`, 평가 `Harness.evals intent` |
| W | 브라우저에서 눈으로 (= 발표 시연 순서) | 미리 보기 창, `/demo` 와 375×812 |

실행:

```bash
cd server && .venv/bin/python -m pytest voice/tests Harness/tests -q
```

```bash
cd server && .venv/bin/python -m Harness.evals intent --systems rule
```

```bash
cd donna-voice/app && npm run typecheck
```

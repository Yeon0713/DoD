## 1. 시작하기 전에

- **켜기**: 미리 보기에서 `donna-voice-app` (`donna-voice/dev-web.sh`가 8090 앱과 8100 음성 백엔드를 같이 켬). 시연 화면 `http://localhost:8090/demo`, 개발자 모드 `http://localhost:8090/dev`. 사장님 앱은 한 곳에만 열어 둘 것 (알림은 먼저 읽은 쪽이 가져감).
- **시험**: `cd server && .venv/bin/python -m pytest voice/tests Harness/tests -q` (지금 306 통과). 앱은 `cd donna-voice/app && npm run typecheck`.
- **일하는 방식**: 이번처럼 [시험 시나리오 문서](test-scenarios-closed-loop.md)에 번호를 먼저 쓰고(예: 인스타 `I1`, 인건비 `B1`), pytest 이름에 같은 번호를 붙이고, 끝나면 "결과" 칸을 채운다. 브라우저 확인은 `/demo` + `/dev`로 한다.
- **결정 기록**: [operating-scenarios.md](operating-scenarios.md) 5장 "정해짐". 이번에 13 ~ 16번을 더했다.
- **페르소나**: 초옹장(s005) 김호찬 사장님. 메뉴·알바생·숫자는 `server/db/data/s005.db`에서 가져오고, 지어낸 값은 "가정"으로 적는다.

### B. 인건비: 조기 퇴근 제안 (개선안 [2]-4 뒷부분, 고리 [1]) — 안 됨, 먼저 결정 필요

- **개선안**: 과거 같은 요일 시간대별 매출 + 당일 예보 + 예약을 견줘 한산할 시간(예: 비 오는 평일 15~17시)을 미리 찾는다. 도나가 먼저 말한다: "오늘 비가 와서 오후 홀 예약이 평소의 40% 수준입니다. 오후 파트 김○○님 1시간 조기 퇴근을 제안해 볼까요? 약 1만 원 절감됩니다." 사장님이 승인하면 알바생에게 확인 알림이 간다.
- **있는 데이터**: `s005.db`의 `staff.hourly_wage`(10,320원), `shifts`(출퇴근 시각), `orders`(시간대별). 메인 서버 `app/weather/`(기상청 API허브, 키가 없으면 목업).
- **없는 것**: 음성 백엔드는 픽스처만 읽음(근무표·시급 없음). 수요 예측. 알바생 화면의 "오늘 일찍 퇴근" 알림.
- **먼저 정해야 함**:
  - 앞서 정한 것과 부딪힌다: "근무표는 받지 않는다"(11/16, [operating-scenarios.md](operating-scenarios.md) 2-3장), "이미 확정된 근무를 줄이라는 제안은 하지 않는다"(11/13 알바생 근무 관리 초안).
  - 사장님 사정으로 일찍 보낼 때의 노동법(휴업수당 등) 검토가 필요하다. 절감액 계산이 달라질 수 있다.

### C. 사장님 말 → 알바생 할 일 (개선안 [2]-4 앞부분) — 일부

- **있음**: 매뉴얼(정적) 6줄, 아쉬운 리뷰 교정 카드(동적), 확인·완료·퇴근 막힘.

  - (실제 백엔드에) "6시 단체석 메밀 알레르기 주의라고 해 줘" 같은 사장님 말 → 할 일
  - 꼭 확인(`must_confirm`)으로 보내기, 보낸 것 취소
  - "시킨 거 다 했대?"
  - 확인 안 한 알바생을 사장님께 다시 알리기 (D-23)
- **쓸 수 있는 것**: 옛 목업 `donna-voice/server/app/requests.py`의 `classify`(L391), `handle`(L442). 지금은 `KNOWN_TASKS`(L44)로 정해 둔 말만 알아들으니, 실제로는 LLM 추출이나 더 넓은 규칙이 필요하다. 읽어 주고 "맞아요?"로 확인하는 흐름은 대본 D-17~D-20 그대로.
- **정해야 할 것**: 날씨 → 할 일("습도 높으니 튀김 반죽 농도 체크")은 11/16 결정("일정·날씨에서 할 일을 스스로 만들지 않는다")과 부딪힌다. 개선안대로 바꿀지 정해야 한다.

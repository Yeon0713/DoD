# 예약·단체 주문, 포스터용 가게 사진·로고

## 1. 예약·단체 주문

손님은 도나를 쓰지 않습니다. 그래서 예약은 **네이버 예약(네이버 플레이스)에서 동기화**한다고 보고, 사장님이 전화로 받은 것은 **앱에서 직접 적습니다**.

| | 어디서 | 처음 상태 |
|---|---|---|
| 네이버 예약 | 서버가 목록을 줄 때 네이버에서 새로 들어온 것을 먼저 가져옴 (**지금은 목업**: `server/db/test_scenarios/<가게>.json`의 `reservations`) | 확정 또는 **문의**(사장님이 받을지 정함) |
| 직접 적기 | 이번 주 › 고른 날 › 예약·단체 주문 › **직접 적기** (예약/단체 주문, 시각, 인원·몇 인분, 메모) | 바로 확정 |

- 문의는 **받을게요**(확정) / **어려워요**(어렵다고 답함)로 정합니다. 진짜 네이버 예약이 붙으면 이때 네이버에 답을 보냅니다. 지금은 기록만 바꿉니다.
- 직접 적은 것만 **지우기**가 됩니다.

### 이번 주 바쁨에 넣는 법 (`server/app/data_pipeline/reservation_effect.py`)
- **확정한** 예약만 넣습니다. 문의와 어렵다고 답한 것은 넣지 않습니다.
- 더하는 매출 = **인원 × 1인 평균 금액**
  - 1인 평균 금액은 최근 8주 주문에서 "주문 금액 ÷ 메인 메뉴 그릇 수"의 평균입니다. 초옹장은 약 1만 원대입니다.
- 예약 시각으로 시간대(점심·저녁·밤)를 정하고, 그 칸의 예상 매출에 더한 뒤 비율로 신호를 다시 정합니다. 1.15 이상이면 **많음 → 그날 "바쁨"**.
- 이유에 `RESERVATION`이 붙고, 이유 글에 "단체 예약 15명" 같은 말이 붙습니다. 이번 주 화면 상자에는 "예약 15명이 있어요"가 보입니다.
- **화면 달력에만 넣습니다.** 계획 엔진이 쓰는 달력(메뉴판·포스터 규칙)에는 넣지 않습니다. 예약 때문에 메뉴판을 바꾸지는 않습니다.

### 초옹장 시험 주간 목업 (모두 지어낸 값)
| 네이버 예약 | 때 | 상태 |
|---|---|---|
| 방문 예약 4명 (창가 자리) | 10/6(화) 12:00 | 확정 |
| 방문 예약 15명 (부서 회식, 수육 미리) | 10/8(목) 18:30 | **문의** → 받으면 10/8 저녁이 바빠짐 |
| 단체 주문 포장 20인분 | 10/9(금) 11:30 | 확정 |
| 방문 예약 12명 (동창 모임) | 11/20(금) 18:00 | 문의 (오늘 기준 주에도 하나) |

### API
| | |
|---|---|
| `GET /api/reservations?store_id=&from=&to=` | 목록 (네이버 동기화 먼저) |
| `POST /api/reservations?store_id=` | 직접 적기 `{"at", "people", "kind", "name", "memo"}` |
| `POST /api/reservations/{id}/confirm` · `/decline` | 문의 받기 · 어렵다고 답하기 |
| `DELETE /api/reservations/{id}` | 직접 적은 것 지우기 |

- 기록: `db/app_data/registry.db`의 `reservations` 표. 바뀌면 그 가게 계산을 지워 이번 주가 바로 다시 계산됩니다.

## 2. 포스터용 가게 사진·로고, 네이버 소식

가게를 등록하거나 다시 불러올 때 네이버 플레이스에서 함께 읽습니다 (`server/app/core/naver_place.py`).

| 항목 | 내용 |
|---|---|
| `photos` | 사장님이 올린 **매장 사진**. 대표 사진이 맨 앞입니다. 손님 사진은 넣지 않습니다 |
| `profile_photo` | 대표 사진 |
| `news` | **소식 탭 카드** (사장님이 올린 알림·이벤트). 제목, 본문, 분류("알림", "EVENT"), 적힌 기간, 올린 날, 사진. 최근 것이 앞 |
| `logo` | 로고 사진 주소. 네이버 플레이스에는 로고 칸이 없어서 **소식 사진 중 로고처럼 생긴 사진**을 찾습니다 |
| `facilities` | 편의 시설. 예: "단체 이용 가능", "예약", "포장" |
| 메뉴 사진 | 전처럼 메뉴마다 |

- 소식은 `m.place.naver.com/place/<id>/feed` 화면에 실린 카드(처음 8개쯤)를 읽습니다. 소식 탭을 못 읽어도 가게 정보는 그대로 등록됩니다.
- 가게 정보 확인 화면(가입 4단계)에 **네이버 소식 N개**와 맨 위 소식 제목, 찾은 로고가 보입니다. 소식 내용을 할 일 계산에 쓰지는 않습니다(아직).
- 네이버 가게 홈 화면에는 매장 사진이 앞쪽 몇 장만 실려 옵니다. 초옹장은 매장 사진 2장(대표 사진 포함)과 메뉴 사진 13장입니다.

### 로고 (`server/app/core/logo_image.py`, `server/app/data_pipeline/store_logo.py`)
- **찾기**: 소식 사진을 10장까지 받아 보고, 다음을 모두 만족하면 로고로 봅니다. 가장 로고다운 것 하나를 씁니다.
  - 테두리가 한 가지 색(바탕)이다 (97% 이상)
  - 그림이 차지하는 곳이 화면의 25% 아래, 그림을 둘러싼 네모가 60% 아래다
  - 색이 몇 가지뿐이다 (가장 흔한 3색이 85% 이상)
  - 초옹장은 "4월 1일 정식 오픈 안내" 소식의 로고 그림이 뽑히고, 음식 사진·안내 포스터 7장은 걸러집니다.
- **바탕 지우기**: 로고를 등록할 때(사장님이 올릴 때, 네이버 소식에서 찾을 때) 자동으로 바탕을 지우고(투명) 둘레 여백을 잘라 PNG 로 둡니다.
  - 지우는 곳: 테두리에 닿은 바깥 바탕, 글자 속 넓은 빈 곳(D·O·A 구멍). 한두 가지 색의 선·글자 로고(예: 초옹장)는 ㅇ 구멍처럼 작은 빈 곳도 지웁니다.
  - 남기는 곳: 바탕과 비슷한 크림색 얼굴, 눈의 작은 하이라이트 (여러 색 그림 로고, 예: 도나 로고).
  - 지운 곳 바로 옆만 반투명으로 해서 가장자리가 매끄럽습니다. 바탕이 한 가지 색이 아니면(사진) 지우지 않습니다.
  - AI 포스터 프롬프트에도 "로고는 바탕을 지운 투명 PNG이니 흰 상자·받침·스티커 없이 포스터 위에 바로 놓으라"고 적습니다 (`server/app/poster_ai/prompt.py`).
- **어디서 오나** (앞선 것을 씀)
  1. 사장님이 앱에서 올린 로고: 포스터 사진 고르기 화면 **가게 로고 › 올리기/바꾸기**. 올리면 서버가 바탕을 지워 `db/app_data/logos/<가게>.png` 로 둡니다.
  2. 네이버 소식에서 찾은 로고: 처음 쓸 때 받아 바탕을 지워 `db/app_data/logos/<가게>.naver-<지문>.png` 로 둡니다. 화면에는 "네이버 소식에서 찾은 로고예요".
  - 올린 로고를 지우면(`DELETE /api/stores/{id}/logo`) 네이버에서 찾은 로고로 돌아갑니다.
- 바탕 지우기에 **Pillow** 를 씁니다 (`server/requirements.txt`). 받아 두기: `pip install -r requirements.txt`

### 포스터
- 서버를 쓰면 포스터는 **AI 포스터**(그날 상황·CLOVA 문구 → ChatGPT 그림, 인스타 스토리 크기)입니다: [poster-ai.md](poster-ai.md). 아래는 목업일 때 앱이 그려 만드는 포스터입니다.
- 사진은 매장 사진·메뉴 사진(네이버) 중에서 고르고, 휴대폰 사진도 고를 수 있습니다.
- 아래 띠에는 **가게 이름과 주소**가 늘 들어갑니다.
- 로고가 있으면 오른쪽 아래에 로고, 없으면 도나가 들어갑니다. 로고는 바탕이 투명해서, 밝은 띠에는 그대로, 어두운 띠(진한 갈색·브랜드색)에는 밝은 둥근 판 위에 얹습니다.
- 네이버 사진(`pstatic.net`)은 서버가 대신 받아 줍니다 (`GET /api/stores/image?url=`). 앱이 포스터 그림 파일에 바로 그릴 수 있게 하려는 것입니다. 다른 주소는 받지 않습니다.

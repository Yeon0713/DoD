# 개발자 대시보드 점검과 최적화 (2026-11-13)

개발자 대시보드(`dev/`, `server/app/modules/dev_tools/`)에서 두 가지가 불편했습니다.
- 가게(계정)를 고를 때마다 너무 오래 걸렸습니다.
- 앱 홈으로 가는 버튼이 바로 보이지 않았습니다.

까닭을 재 보고, 쓸모없거나 겹치는 기능을 정리했습니다. 쓰는 법은 [dev/README.md](../dev/README.md)에 있습니다.

## 1. 무엇이 느렸나 (고치기 전에 잰 값)

| 언제 | 걸린 시간 | 까닭 |
|---|---|---|
| 시연 탭에서 가게를 처음 고를 때 | s001 **34.5초**, s003 21.6초, s101 4.2초 | 시연 기간 2주 × 하루 알림 3번 = 42개 시각을 하나씩 계산하면서, **시각마다 DB 전체를 다시 읽었습니다** (한 번에 0.58초. 분석·계획은 0.39초) |
| 서버를 다시 켠 뒤 | 다시 처음부터 | 결과를 서버 메모리에만 기억했습니다 |
| 시연 단계를 누를 때마다 | 1초 + CLOVA | 가게를 다시 계산하고 CLOVA 답글 초안을 기다렸습니다(평균 1.7초). 뒤에서 문장 다듬기 CLOVA도 수십 번 나갔습니다 (로그: 1분에 26번) |
| 분석·알림 타임라인 탭 | 1초 + CLOVA | 계산한 지 10분이 지났으면 탭을 열 때마다 다시 계산했습니다 |
| 개요·매장·시스템·AI 탭 | 0.02초 이하 | 문제 없음 |

앱 홈 버튼이 안 보인 까닭은 세 가지였습니다.
- 휴대폰 틀이 처음에 비어 있었습니다. 앱 홈은 82개 단계 가운데 UC03 "09-h0"에 섞여 있었습니다.
- 화면 폭이 1200px보다 좁으면 휴대폰 틀과 [이전]/[다음]이 단계 목록 아래로 밀렸습니다.
- 주소의 `#탭이름`만 바꾸면 탭이 바뀌지 않았습니다.

## 2. 고친 것 (진행 순서)

| 번호 | 고친 것 | 결과 | 파일 |
|---|---|---|---|
| 1 | 시연 훑기에서 DB를 **한 번만** 읽고, 시각마다 그때까지의 행만 남겨 씁니다 (`inputs_until`, `plan_at_times`) | s001 34.5초 → **13.9초**, s003 21.6 → 8.4초, s101 4.2 → 2.0초. 결과는 고치기 전과 **글자 하나까지 같음** (4개 가게 전체 비교) | `data_pipeline/db_rows_to_analysis_inputs.py`, `data_pipeline/store_snapshot_cache.py`, `modules/dev_tools/demo_week_scan.py` |
| 2 | 훑은 결과를 파일(`server/db/app_data/demo_scans/<가게>.json`, git 제외)에 남기고 다시 씁니다. 결과에 **지문**을 붙여, 가게 DB·공통 DB·그 가게의 등록 정보·사장님이 고친 설정·계산 코드 중 하나라도 바뀌면 다시 훑습니다 (다른 가게를 등록하거나 초기화로 지워도 이 가게 결과는 그대로) | 서버를 다시 켜도 가게를 고르면 **0.02초** | `modules/dev_tools/demo_week_scan.py` |
| 3 | 서버가 켜지면 모든 가게를 뒤에서 미리 훑습니다 (`DEV_TOOLS_ENABLED=true`일 때만). 훑는 동안 대시보드에 "훑는 중 n / 42"를 보여 줍니다 (`GET /api/dev_tools/demo_progress`) | 가게를 고르면 바로 열림 (0.01초) | `app/main.py`(lifespan), `modules/dev_tools/router.py`, `dev/app.js` |

| 5 | 분석·알림 타임라인 탭은 **계산해 둔 결과**를 보여 줍니다. 맨 위에 "n시에 계산해 둔 결과예요 [다시 계산]"이 있습니다. 한 번도 계산하지 않은 가게만 처음 한 번 계산합니다 | 탭이나 가게를 바꿔도 0.005초 | `modules/dev_tools/data_provider.py`(`_kept_snapshot`), `dev/app.js` |
| 9 | 시연 단계 갱신: 새 시작 화면 **10-s1b**(`/start`)와 **10-s2**(`/start/choose`)를 UC01에 넣었습니다. 가입 흐름에서 빠진 09-3(`/start/notify-time`), 바로 다음 화면으로 넘어가는 09-2n(`/start/naver`), 들어오는 길이 없는 09-2i(`/start/hours`)는 뺐습니다 | 지금 앱과 시연 단계가 맞음 | `modules/dev_tools/demo_scenario.py` |

| 10 | 주소의 `#탭이름`을 바꾸면 그 탭으로 갑니다. 예전 탭 이름도 받습니다 | 링크로 탭 공유 | `dev/app.js` |

| 뺀 것 | 까닭 |

## 3. 고친 뒤 잰 값

| 언제 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 시연 탭에서 가게 고르기 (미리 훑은 뒤) | 34.5초 (s001) | 0.01초 |

## 4. 확인한 것

- 서버 테스트: 374개 통과, 18개 건너뜀. 새로 넣은 `tests/modules/test_dev_tools_speed.py` 10개가 위 동작을 지킵니다.
  - 한 번 읽고 거르기 = 시각마다 읽기
  - `plan_at_times` = `plan_only`
  - 파일 저장 뒤 다시 쓰기
  - 설정이 바뀌면 다시 훑기
  - 지우기
  - 진행 API
  - 초안 기다리지 않기
  - 분석 탭이 계산해 둔 결과 쓰기
  - 기록 지우기 API 없음
- 테스트는 훑기 결과 파일을 임시 폴더에 씁니다 (`tests/conftest.py`).
- 대시보드 화면(저장소 복사본 서버)에서 확인한 것:
  - 진행 표시와 [앱 홈]
  - 처음 띄운 앱 홈
  - 좁은 화면에서 휴대폰 틀이 맨 위로 오는지
  - 상태·AI·분석·조작 탭
  - `#usage` → AI 탭, `#status`로 바꾸면 이동

## 5. 통합 테스트에서 고친 것 (2026-11-13)

브라우저에서 대시보드와 휴대폰 틀 속 앱을 직접 눌러 보며 찾은 문제입니다.

| 문제 | 고친 것 |
|---|---|
| 서버만 예전 코드일 때 시연 탭이 통째로 실패 | `demo_progress` 가 없어도 준비 줄만 빼고 그립니다 |
| 좁은 화면에서 [다음]을 누르면 페이지가 단계 목록으로 굴러가 휴대폰 틀이 밀림 | 단계 목록 칸 안에서만 굴리고, 단계를 열면 휴대폰 틀로 올립니다 |
| 데모 초기화 뒤 목업 가게 결과까지 다시 훑음 | 지문에 등록 기록 파일 전체가 아니라 그 가게의 등록 정보만 넣었습니다 |

| 누르는 곳이 안 보임 | 대시보드에도 시연용 마우스 표시(`?cursor=1`, `dev/cursor.js`), 휴대폰 틀 속 앱에도 같이 켬 |

## 6. 남은 것

- 미리 훑기는 4개 가게를 차례로 하므로, 서버를 켜자마자 마지막 가게를 고르면 앞 가게가 끝날 때까지 몇 초 기다릴 수 있습니다.
- 시연 휴대폰 틀의 앱은 앱(8082)이 붙은 서버를 봅니다. 대시보드와 앱이 같은 서버(8000)에 붙어 있어야 시계 옮기기가 앱 화면에 반영됩니다.

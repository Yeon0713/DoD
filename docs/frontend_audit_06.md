# 도나 앱 프론트엔드 감사 보고서 (UI/UX, 기능)

- **대상**: `mobile/` (React Native + Expo SDK 58, Figma 06 시안 반영본), 브랜치 `jheroorehj/feat-frontend`, 커밋 전 작업 트리
- **날짜**: 2026-11-11
- **원칙**: 이번 감사에서 소스코드는 고치지 않았다. 새로 만든 파일은 이 보고서와 `docs/audit_06_screens/`의 스크린샷 2장뿐이다.
- **검토자 주의**: 이 앱의 대부분은 같은 세션에서 구현했다. 독립 검토자 관점으로 다시 보았지만, 구현자가 놓치기 쉬운 가정이 남아 있을 수 있다. 실제 사장님 사용성 테스트는 하지 않았다.

확인 상태 표기: **재현됨**(직접 실행해 관찰), **코드상 확인**(코드로 확인, 실행으로는 못 봄), **추가 검증 필요**.

## 1. Executive Assessment

**요약: 데모와 내부 검토용으로는 쓸 수 있고, 실제 사장님에게 내놓기 전에는 P1 3건과 P2 일부를 먼저 고쳐야 한다.**

잘 된 부분:

- 핵심 흐름(오늘 카드 처리, 답글, 점검, 메뉴판, 포스터, 처음 설정, 설정, 이번 주, 매출)이 목업만으로 끝까지 이어진다.
- 불러오는 중, 인터넷 끊김, 동작 실패, 빈 상태가 화면마다 구현돼 있고 실패해도 입력한 내용이 남는다.
- 타입 검사 오류 없음. 새로 불러온 화면에서 콘솔 오류 없음. 글자 색 대비는 토큰 조합 모두 4.5:1 이상이다(가장 낮은 본문 조합 `ink-3`/`paper` 5.33).
- iOS에서 Safe Area, 한글 키보드가 올라올 때 아래 버튼 처리, 폰트와 그림이 정상이다.

부족한 부분:

- **첫 실행 진입로가 없다.** 처음 설정 화면은 있지만 앱이 그리로 보내지 않는다.
- **입력 검증이 비어 있다.** 빈 답글을 그대로 올릴 수 있다.
- **화면 높이와 글씨 크기에 약하다.** 작은 화면이나 큰 글씨에서 오늘 화면의 주 버튼이 화면 밖으로 밀린다. 대상 사용자(디지털에 익숙하지 않은 사장님)를 생각하면 영향이 크다.
- 06에서 넣은 "요일별 장사 시간"이 화면 문구에는 반영됐지만 알림 예약, "나중에" 시트, "다음 알림" 문구에는 반영되지 않아 약속과 동작이 어긋난다.
- 자동 테스트와 린트가 없어 회귀를 막을 장치가 없다.

발견 건수: P0 0건, P1 3건, P2 10건, P3 6건.

## 3. Findings

### P1

#### F-01. 처음 쓰는 사람이 처음 설정을 거치지 않고 바로 오늘 화면에 들어간다
- **분류/심각도**: UX, Functional / P1
- **화면/파일**: 앱 시작. `src/app/_layout.tsx`, `src/lib/localStore.ts`(`onboarded`), `src/components/start/StartScreens.tsx:498`
- **증상**: 저장 값을 모두 지우고 `/`를 열면 처음 설정 없이 오늘 화면이 뜨고 데모 카드가 나온다. 이때 저장된 `dona.prefs.v1`은 없다(`onboarded: false`).
- **재현**: `/dev` → "처음부터 다시" → `/` 열기.
- **증거**: `onboarded`를 읽어 화면을 가르는 코드가 없다. 쓰는 곳은 `StartScreens.tsx:498`, `DevScreen.tsx` 두 곳뿐이다.
- **원인**: 진입 분기(게이트)가 구현되지 않았다. Next.js 판도 같았다.
- **영향**: 가게 확인, 장사 시간, 알림 시간, 알림 허락을 모두 건너뛴다. 알림이 예약되지 않으므로 "하루 3번 알림"이라는 제품의 핵심이 동작하지 않는다.
- **권장**: 루트 레이아웃에서 `prefs.onboarded`가 false면 `/start`로 보낸다(expo-router `Redirect` 또는 보호 라우트). `/dev`의 화면 바로 가기는 이 분기를 우회할 수 있게 둔다.
- **검증**: 초기화 후 실행 → `/start`가 뜨는지, 끝낸 뒤 다시 실행 → 오늘 화면인지.
- **상태**: 재현됨

#### F-02. 빈 답글을 저장하고 그대로 올릴 수 있다
- **분류/심각도**: Functional / P1
- **화면/파일**: 답글 고쳐 쓰기, 오늘 카드. `src/components/reply/ReplyScreens.tsx:170-177`(저장), `:86`, `:152`(`saved[planId] ?? …`), `src/lib/cards.ts` `replyDraft`
- **증상**: 글을 모두 지우고 "다 고쳤어요"를 누르면 빈 글이 저장된다. 오늘 카드에 빈 말풍선이 보이고 "이대로 답글 달기"가 그대로 성공한다("답글을 맡겼어요, 내일 오후 2시에 올릴게요").
- **재현**: 단골 답글 카드 → 고쳐 쓰기 → 전부 지움 → 다 고쳤어요 → 이대로 답글 달기.
- **증거**: 저장 값 `{"REVISIT_REPLY:rv_102:2026-11-18":""}`. 빈 문자열은 `??`에서 기본 초안으로 돌아가지 않는다.
- **원인**: 저장과 게시 어디에도 빈 글, 공백만 있는 글 검사가 없다. 길이 제한도 없다.
- **영향**: 실제 연결 뒤에는 손님에게 빈 답글이 올라가거나 서버 오류가 난다. 사장님 이름으로 나가는 글이라 되돌리기 어렵다.
- **권장**: 공백을 뺀 글이 비면 "다 고쳤어요"를 끄고 한 줄 안내를 보인다. 게시 함수에서도 한 번 더 막는다. 배달앱별 글자 수 제한을 확인해 `maxLength`를 건다. 대안: 빈 글이면 도나 초안으로 되돌리기(사장님 의도와 다를 수 있어 안내가 필요하다).
- **검증**: 빈 글, 공백만, 아주 긴 글로 저장과 게시 시도.
- **상태**: 재현됨

#### F-03. 화면이 낮거나 글씨가 크면 오늘 화면의 주 버튼이 화면 밖으로 밀린다
- **분류/심각도**: UI, Accessibility / P1 (대상 기기와 글씨 설정에 따라 P2)
- **화면/파일**: 오늘. `src/components/today/TodayScreen.tsx:316-344`, `src/components/ui/TabPage.tsx`
- **증상**:
  - 360×640, 알림 꺼짐 띠 + 긴급 카드: "이대로 답글 달기"와 "나중에 할게요"가 첫 화면에 전혀 보이지 않는다. 스크롤해야 나온다.
  - 320×568: 주 버튼 위쪽이 y=671로, 보이는 영역(탭 위 490px) 밖이다.
  - iPhone 18 Pro, 가장 큰 일반 글씨: "나중에 할게요"가 탭 바에 반쯤 가려진다 (`docs/audit_06_screens/ios_today_xxxl.png`).
- **재현**: 화면 크기를 360×640으로 두고 `/dev`에서 금요일 21:35 → 오늘.
- **원인**: 버튼이 스크롤 내용 맨 아래에 붙어 있다. 내용이 화면보다 길면 버튼이 같이 내려간다. 스크롤할 수 있다는 표시도 없다.
- **영향**: "한 화면에 할 일 하나, 보고 누르기만"이라는 설계 원칙이 작은 화면에서 깨진다. 글씨를 키워 쓰는 사용자가 버튼을 못 찾을 수 있다.
- **권장**: 주 버튼과 보조 버튼을 스크롤 밖 아래에 고정한다(`SubPage`의 `footer`와 같은 방식). 내용만 스크롤된다. 대안: 카드 내용을 줄이는 방식은 06 시안의 정보(리뷰 2줄, 초안)를 다시 깎아야 해서 권하지 않는다.
- **검증**: 360×640, 320×568, 큰 글씨, 손쉬운 사용 글씨에서 버튼이 늘 보이는지.
- **상태**: 재현됨 (안드로이드 실제 기기는 추가 검증 필요)

### P2

#### F-04. 아래 탭 글자의 아랫부분이 잘린다 (아래 여백이 0인 기기)
- **분류/심각도**: UI / P2
- **파일**: `src/app/(tabs)/_layout.tsx` (`height: 78 + insets.bottom`, `paddingTop/Bottom: 10`)
- **증상**: 웹에서 탭 글자 상자 높이가 15px인데 글자 줄 높이는 20px이고 `overflow: hidden`이다. "오늘", "이번 주" 아래가 잘려 보인다. iPhone 18 Pro(아래 여백 34)에서는 정상이다.
- **원인**: 탭 항목에 남는 높이는 57px인데 아이콘 28 + 간격 + 글자 20과 항목 기본 여백의 합이 이를 넘는다.
- **영향**: 홈 표시줄이 없는 기기(버튼식 안드로이드, iPhone SE)에서 같은 조건이라 같은 증상이 예상된다.
- **권장**: 높이를 86 안팎으로 올리거나 위아래 여백을 6으로 줄인다. 글자 상자에 고정 높이를 주지 않는다.
- **검증**: 웹에서 글자 `scrollHeight == clientHeight`, 안드로이드 에뮬레이터 눈으로 확인.
- **상태**: 재현됨(웹). 안드로이드, iPhone SE는 추가 검증 필요

#### F-05. 빠르게 두 번 누르면 화면이 두 번 열리고, 답글이 두 번 올라갈 수 있다
- **분류/심각도**: Functional / P2
- **파일**: `src/components/ui/parts.tsx`(`PrimaryButton`, `SecondaryButton`), `src/components/ui/nav.ts`, `TodayScreen.tsx:272-313`
- **증상**: "리뷰 보기"를 연달아 두 번 누르면 점검 화면이 2장 쌓인다(기록 +2, 뒤로를 두 번 눌러야 오늘로 온다).
- **코드상**: 바로 올리기는 `disabled={sending}`으로 막지만 상태가 반영되기 전의 두 번째 누름은 `publishReply`를 한 번 더 부른다. 목업이라 겉으로는 안 보인다.
- **영향**: 뒤로 가기가 헷갈리고, 실제 연결 뒤 같은 답글이 두 번 올라갈 수 있다.
- **권장**: 이동은 같은 주소로 연속 push를 막고(`router.navigate` 또는 짧은 잠금), 게시는 `useRef` 잠금으로 즉시 막는다. 서버에는 중복 방지 키를 요청한다.
- **검증**: 같은 버튼을 동기적으로 두 번 클릭해 기록 길이와 호출 횟수 확인.
- **상태**: 화면 중복 재현됨, 게시 중복은 코드상 확인

#### F-06. 장사 시간 저장 오류가 화면 밖에 뜨고, 고쳐도 사라지지 않는다
- **분류/심각도**: UX / P2
- **화면/파일**: 처음 설정 장사 시간(06-2i), 설정 장사 시간. `src/components/start/HoursEditor.tsx`, `StartScreens.tsx`
- **증상**: 모든 요일을 끄고 "이대로 좋아요"를 누르면 오류 상자가 y=844~940에 생긴다. 화면 높이는 812이고 아래 버튼이 y=736부터 덮고 있어 아무 일도 안 일어난 것처럼 보인다. 그 뒤 요일을 다시 켜도 "쉬는 날이 아닌 날이 하루는 있어야 해요"가 남아 있다.
- **원인**: 오류를 스크롤 내용 맨 끝에 붙이고, 그 자리로 스크롤하지 않는다. 입력이 바뀌어도 오류 상태를 지우지 않는다.
- **영향**: 처음 설정 3단계에서 이유를 모른 채 막힌다.
- **권장**: 오류를 버튼 바로 위(고정 영역)에 보이거나 오류 위치로 스크롤한다. 입력이 바뀌면 오류를 지운다. 가능하면 저장 전에 막는다(전부 쉬는 날이면 버튼 끄기).
- **검증**: 같은 조작 후 오류가 보이는 영역 안에 있는지, 수정하면 사라지는지.
- **상태**: 재현됨

#### F-07. 요일별 장사 시간이 알림 예약, "나중에" 시트, "다음 알림"에 반영되지 않는다
- **분류/심각도**: Functional / P2
- **파일**: `src/components/start/notify.native.ts:8-18`, `TodayScreen.tsx:161-174`(`LaterSheet`), `:141`(`nextSlot`)
- **증상(코드상)**:
  - 알림은 매일 같은 시각 3개로 예약된다. 쉬는 날에도 울리고, 일찍 닫는 날의 마감 전 알림도 당겨지지 않는다.
  - "나중에" 시트와 "다음 알림은 내일 출근 후 10:30"은 `settings.slots`만 읽는다. 내일이 쉬는 날이어도 "내일 출근 후"를 제안한다.
  - "나중에"를 골라도 그 시각에 알림이 예약되지는 않는다. 띠는 "다시 알려 드릴게요"라고 말한다.
- **근거**: 화면은 "일요일은 일찍 닫아서 마감 전 알림을 19:30에 보내요", "쉬는 날엔 알림을 보내지 않아요"라고 안내한다. 계산 함수 `slotTimeOn`, `slotAtOn`(`src/lib/hours.ts`)은 이미 있다.
- **영향**: 안내와 실제가 달라 신뢰를 잃는다. 대상 사용자는 AI를 경계하는 편이라 더 민감하다.
- **권장**: 요일별 주간 예약(요일 × 3개, 쉬는 날 제외)으로 바꾸고, 시트와 "다음 알림"은 `slotAtOn`으로 계산한다. 서버 푸시로 갈 계획이면 그때까지 안내 문구를 낮추는 대안도 있다.
- **검증**: 월 휴무, 일 20시 마감 설정에서 예약 목록(`getAllScheduledNotificationsAsync`)과 시트 선택지 확인.
- **상태**: 코드상 확인 (알림 도착은 미검증)

#### F-08. 한국어 문장이 단어 중간에서 줄이 바뀐다
- **분류/심각도**: UI / P2
- **화면/파일**: 글이 두 줄 이상인 모든 곳. 공통 `Text` 사용처, `src/global.css`
- **증상**: "다 식어서 왔/어요", "감사합니/다", "남/겨요", "많아/요", "이/어져요". 웹과 iOS 모두.
- **원인**: Next.js 판은 `word-break: keep-all`을 썼다. 앱에는 대응 설정이 없다.
- **영향**: 읽기 어렵고, Figma 시안(어절 단위 줄바꿈)과 다르다.
- **권장**: iOS는 `Text`에 `lineBreakStrategyIOS="hangul-word"`, 웹은 `word-break: keep-all`. 공통 글자 부품 하나를 만들어 거기서 준다. 안드로이드는 같은 속성이 없어 `textBreakStrategy`로 얼마나 나아지는지 확인이 필요하다.
- **검증**: 위 문장들을 375, 360 폭에서 다시 확인.
- **상태**: 재현됨

#### F-09. 없는 할 일 주소를 열면 그럴듯하지만 틀린 화면이 나온다

- **파일**: `src/components/poster/PosterScreens.tsx`, `naver/NaverScreens.tsx`(메뉴 순서), `week/WeekScreens.tsx`(자세히), `reply/ReplyScreens.tsx`(묶음)

#### F-11. 장사 시간 입력에 손이 많이 간다
